## 桌面环境适配

番茄 Todo 是 Linux 桌面应用，任务、番茄钟、统计、备份等主体功能在各主流桌面环境都可用。与桌面深度耦合的两项能力——**专注保护**和**定时锁机**——目前只在 **niri / Wayland** 上完整可用，因为它们需要通过 niri IPC 获取前台窗口并把不允许的应用切回番茄 Todo。

| 桌面 / 会话                          | 任务、计时与统计 | 专注保护与定时锁机 | 托盘与自启动                        |
| ------------------------------------ | ---------------- | ------------------ | ----------------------------------- |
| **niri / Wayland**（主要验证环境）   | ✅               | ✅ 完整可用        | ✅                                  |
| 其他 Wayland 合成器（GNOME、KDE 等） | ✅               | ⚠️ 按钮显示不可用  | ✅ 需 AppIndicator / StatusNotifier |
| X11                                  | ✅               | ⚠️ 按钮显示不可用  | ✅ 需 AppIndicator / StatusNotifier |

- **niri / Wayland**：程序优先使用原生 Wayland，让窗口 PID 和应用标识能被正确识别；即使启动终端设置了 `GDK_BACKEND=x11`，也不会因此误用 Xwayland 中转窗口。
- **GNOME、KDE、其他 Wayland 合成器和 X11**：仍可使用任务与计时功能，但保护与锁机按钮会显示不可用。
- **托盘**：需要 AppIndicator 运行库（Arch 的 `libappindicator-gtk3`，Debian 的 `libayatana-appindicator3-1`）及桌面上的 StatusNotifier 托盘组件。程序会检测组件是否存在：没有托盘时正常显示窗口和退出，后台启动会等待桌面组件最多约 10 秒后显示窗口。保护专注中拒绝从托盘隐藏、暂停或退出。
- **自启动**：配置为 `$XDG_CONFIG_HOME/autostart/studio.tomato.todo.desktop`。Linux 桌面在用户登录后读取该项；niri 会话需要启用 XDG 自启动目标。仅在本机保存的桌面偏好为 `$XDG_CONFIG_HOME/studio.tomato.todo/desktop.json`，不会随任务备份导入到其他电脑。
- **系统运行库**：程序依赖系统 GTK 3 和 WebKitGTK 4.1（Arch 为 `gtk3` / `webkit2gtk-4.1`，Debian / Ubuntu 为 `libgtk-3-0` / `libwebkit2gtk-4.1-0`）。
- **构建兼容性**：此构建在当前 Linux x86_64 环境验证，不保证直接兼容所有发行版的旧版 glibc；发布用 Debian 安装包在 CI 的 Ubuntu 22.04 上构建，以覆盖较旧的发行版。

## 运行

本次已构建的程序：`target/release/tomato-todo`。在项目根目录执行：

```sh
./target/release/tomato-todo
```

Debian 安装包位于 `target/release/bundle/deb/`。已发布的版本见 [Releases](https://github.com/AntheaLaffy/tomato-todo/releases)：Debian / Ubuntu 下载 `.deb`，其他发行版可解压 `*-x86_64-linux.tar.gz` 后用其中的 `install.py` 安装。

Arch / niri 可直接安装到用户目录，无需 root：

```sh
python3 scripts/install.py --autostart --pin-dms
```

`--autostart` 启用登录后后台启动；`--pin-dms` 为现有 DankMaterialShell 栏添加固定入口。其他桌面可省略 `--pin-dms`。程序安装在 `~/.local/lib/tomato-todo/`，命令入口为 `~/.local/bin/tomato-todo`，应用列表入口为 `$XDG_DATA_HOME/applications/tomato-todo.desktop`（默认 `~/.local/share/applications/`）。快捷栏采用窗口实际的 `tomato-todo` 标识来匹配图标与现有窗口。修改 DMS 配置前会保存备份，重复安装不会重复添加入口。使用 `--pin-dms` 后执行 `dms restart` 刷新桌面栏；本次已安装并刷新。

## 为什么做这样一个工具

它想解决的不是「怎么计时」，而是「怎么让专注更容易发生」。

- **环境胜过意志力。** 专注时，不在白名单里的应用会被自动切回专注界面；你不必每次都战胜自己，只需提前把环境设好。
- **让 AI 维护你的环境。** 学习计划和每个项目的专属应用白名单都是可读写的 JSON：把「英语任务需要词典和浏览器」告诉 AI，改完文件再导入即可。过去几乎不值得维护的个性化配置，现在是一句话的事。
- **桌面级、躲不掉。** 登录自启动、系统托盘常驻，关掉窗口也继续计时。
- **只属于你。** 任务、统计和设置都在本机，不联网、不要账号。
- **开源，可以接着改。** 核心是 Rust，计划格式与文档公开；欢迎用智能体按自己的需求继续扩展。

## 模板、印刷与实例

创建入口默认是只做这一次的临时任务，也可选择保留为手动模板或自动模板。可选备注/步骤、分类和专注安排按需展开，周期或日程按所选规则显示，预印配置仅自动模板显示。填写预计分钟数即可自动安排专注，不要求用户计算番茄数；短任务自动缩短单次专注，其他任务向上预留完整时段并预览含休息的总计划块。模板保存标题、备注、步骤、项目、单次时长、标签和默认优先级，再选择非重复日程或每周周期。一个开始时间对应多个日期或周期单元，可在一份模板里添加多个开始时间，共用任务内容。临时任务也能一次印完整份日程。类别由管辖与时间/重复属性推导。日期、完成、统计属于已印实例，实例不保存重复规则，完成实例不会生成下一条。

「自动印刷」是独立选项。关闭时保留静态模板，随时手动选择起止日期，批量印刷所选日程或日期涉及的整个周期；开启时每次运行/轮询滚动补齐近期安排，默认提前 7 天，可设 0–90 天。重复模板每次印完涉及的完整周；非重复日程补齐截止预印日期的安排，包括尚未报废的逾期日程。印刷会补齐范围内的遗漏，不依赖日期首次进入窗口；同模板同日期不会重复印刷，删除实例也不会重建。程序关闭期间不执行，运行后跳过已报废的候选，逾期但仍可重修的实例进入待补队列。

普通组的重修窗口以分钟计，从计划块结束起算，仅当天有效，默认 0；目标实例由配对节点的信号裁定管理，习惯不重修。模板修改只影响未来，显式「同步到未完成实例」才更新现有形状，保留实例日期、管辖、步骤进度及专注历史。删除模板保留实例。编辑器也保留直接创建一条实例的快捷方式。

计划文件为 v4，完整备份和本机数据为 v3，包含主线节点、配对、信号与永久 ID 历史。旧 v1/v2 计划继续转换；不含旧目标模型的 v3 计划可导入。旧本机数据/备份需要先转换，不自动套用旧目标截止规则。没有默认用户模板或私人资料。规范与示例见 [计划文件](docs/PLAN_FORMAT.md) 和 [备份文件](docs/BACKUP_FORMAT.md)。

## 设计理念：任务、目标、习惯、项目与愿景

目标组承载主线，组内可有听课、练习、实验等不同任务，不设置统一产出单位。组和节点的 ID 不随名称或规则改变；独立实体的 ID 在当前数据中全局唯一，删除后仍永久保留，不能用于新实体。

### 主线节点与配对

在「目标、习惯与愿景 → 目标」中新建目标组，编辑主线并添加节点。实例仍由模板印刷；实例的所属目标组标识符及计划执行开始时间共同决定节点配对，提前印刷不会改变执行日期。节点区间为包含起点、不包含终点，按时间排列且不重叠；有日期但没有提醒时刻的实例按当天 00:00 配对，无日期实例暂不配对。

每个节点显示配对数量、任务完成情况与最终结果。默认要求至少配对一条任务且配对任务全部完成，可增加数量要求或人工确认。没有实例不算完成。删除实例保留配对记录，未完成的被删任务不会变成完成；调整未裁定任务的所属组或执行时间会重新配对，编辑主线范围则保留已有配对。

### 信号裁定与阻断

节点没有自行过期状态。完成只是过程信息，成功/失败由信号裁定：普通节点默认不发信号；有权限的节点可以按时间，或时间与自身完成情况共同触发成功/失败信号，方向可向头或向尾。成功与失败信号不检查接收节点是否完成，且裁定不可撤销。发出者接受自己的信号。

有发信号权限的节点可分别为成功和失败信号设置不阻断、无条件阻断或基于配对/完成状态的条件阻断。拒绝时该节点不接受裁定，传播停止；普通节点不阻断。末节点的检查信号固定向头传播，不可阻断，只把已完成且尚未裁定的节点变成成功。

节点成功或失败后，所有配对实例都报废，已经完成的记录仍保留；正在进行的该实例专注会停止并记录实际已用时间。模板的印刷安排独立存在，后来进入已裁定节点的实例同样报废。尚未配对的目标实例没有默认截止期限。信号记录可查看发出者、裁定内容、接收路径和阻断原因。

普通非目标实例仍使用静态重修窗口，习惯仍在计划块结束后报废并统计缺勤。目标组与习惯组互斥；目标模板允许单次、日程或周期规则，提醒时间可选。

具体语义与实现边界见 [主线与节点设计](docs/NODE_DESIGN.md)。

### 项目是另一个维度

项目的管辖与目标、习惯**相互独立**——不是上下级，也不是平级，而是两个正交的轴：

- 目标 / 习惯回答「**这件事该怎么执行、漏了怎么办**」；
- 项目回答「**做这件事时，该处在什么环境里**」。

项目的抽象意义在于**构造学习环境**：不同类型、不同科目的任务需要不同的环境（放行哪些应用、屏蔽哪些干扰）。所以专属应用白名单挂在项目上，而不是挂在目标或习惯上——同样是「听课」，英语课和编译原理课需要的软件并不一样。

一个任务可以同时属于某个项目和某个目标/习惯：项目负责环境，目标或习惯负责执行语义。

### 愿景：天马行空的理想

愿景的前身是「**开放性任务**」——一个没有期限、可以一直做的任务。但分析下来发现：没有边界、没有进度、没有成败，所谓「开放任务」其实就是**画大饼**，硬塞进任务体系只会把执行语义搅浑（它到底算不算完成？漏了算不算失败？）。所以它被请出任务体系，变成纯标记的愿景：不再假装自己是待办，只老老实实当地图上的一个方向。

任务是具体的，目标是具体的，习惯也是具体的——它们都**脚踏实地**：有明确的时间、明确的进度、明确的成败。

愿景不一样。愿景是**天马行空的理想**：它关心的不是「今天做什么」，而是「以后想成为什么样的人」。所以它不参与任何执行语义——不补进度、不失败、不计缺勤，也不会因为哪天没做而欠账。它只是写给你自己的一段话：想考的学校、想过的生活、一张研究生工资的截图。

- 愿景可以挂在**项目**下（英语一 → 80 分）、挂在**目标**下（OpenCamp → 拿结营证书），也可以挂在**顶层**当总愿景（考上北大）。
- 「目标·习惯·愿景」页的**愿景**分页把它们汇总起来，配着各自的小作文。

## 已实现

- **关键节点音效**：开始/继续/暂停计时、提前结束、专注完成、进入/结束休息、任务完成、到点提醒、开始/结束锁机时播放简短声音；学习过程中不循环打扰。偏好设置里可关闭、调节音量（默认 40%）与逐项试听；背景音独立控制。本地合成，无网络与额外音频依赖。浏览器/桌面 WebView 需首次点击或按键激活音频；激活前的提示不补播，窗口与文字提醒照常工作。

- 任务与项目：增删改、完成与撤销、优先级、截止日期、标签、备注、子任务、单次/每周分时模板印刷；搜索、筛选和排序。列表可多选**删除任务**或**移出**（从所属项目/目标/习惯中摘出，任务本身保留）；要同时改项目、优先级、时间、重复等多个字段，建议直接进任务编辑弹窗（批量只适合粗调）。
- 目标：把长期的事（如 OpenCamp 课程）建成目标，把听课、作业等任务挂到同一目标下；目标按「数量」或「时长」累计进度，漏做的目标任务会作为「待补」出现在今日专注，直到补完。
- 任务类别（自动推导，不手填）：属于某个目标＝主线管辖，配对节点尚未裁定时可待补，裁定后报废；不属目标、**有提醒时间且重复**＝养习惯，过期后从今日待办移出并计一次缺勤；其余（无提醒、定时但不重复、不定时的重复）＝普通番茄钟。
- 习惯：把每天要做的事建成「习惯」，可以为不同星期设置不同时段（例如午饭随当天课表变化）；程序按预印范围生成各天的实例，过期未做从今日待办移出并计缺勤。习惯与目标都在「目标与习惯」页管理。
- 愿景：给项目、目标或整体写一段「想要什么」的标记（如「英语一 80 分」「考上北大」）；**不参与**任务、进度与缺勤，只做方向与激励，在「目标·习惯·愿景」页的愿景分页汇总。
- 可选时间安排：任务可填写提醒时刻、单次专注时长和重复周期；灵活任务留空即可。到点唤出窗口、高亮任务，一键开始；正在计时、暂停计时或锁机时延后。提醒只在计划块内有效（番茄数 × 单次时长，加上番茄之间的休息），普通组可在重修窗口内待补，超过报废时间不再提醒；跨日不补。养习惯过期后从今日待办移出（计入缺勤），定目标保留为待补。程序需保持运行，电脑休眠时不唤醒。
- 番茄钟：自定义专注/短休息/长休息，暂停、继续、跳过、重置、任务关联、循环与自动衔接。计时由 Rust 管理，重启后按实际截止时间恢复，不把应用关闭期间虚构成连续完成的番茄。
- 统计：当天专注时间、完成番茄、连续天数、近七天趋势、项目时间分布与专注历史；提前结束也保留实际用时，但不计为完成番茄。另有两块围绕成败的视图：**主线**按「整条线全部节点成功才算成功、任一失败即失败」给出每个目标组的结果与逐节点时序；**纵切面**把近两周每天的完成、缺勤、作废与主线成功/失败/报废并排，便于看同一时段里主线与其它任务的相互影响。成功因要求全线通过而少见，失败与未完成更值得回看。
- 专注体验：沉浸计时、合成雨声与棕噪声、音量、结束铃声、系统通知、置顶、明暗/跟随系统主题、键盘快捷键。
- 桌面集成：应用菜单与图标、单实例唤回、登录自启动、系统托盘菜单（打开、开始/暂停、收起、退出）。默认关闭窗口收起到托盘并继续计时；“偏好设置 → 桌面集成”可调整。完全退出会结束当前计时并保留实际用时。
- 学习计划：独立的 JSON v4 文件标准（可转换导入 v1/v2），导出未完成实例、模板、主线与项目。导入是**以文件为准的配置更新**：相同 ID 的任务、目标节点、模板与项目按文件更新，完成进度、专注历史与节点裁定一律保留；文件没有提到的实体默认不动，加 `"replace": true` 时改为整份同步、移除文件未提及的未完成任务与容器。项目的 `appWhitelist`（个性应用白名单）随计划文件导出并按项目覆盖，便于用 AI 维护。
- 完整备份：SQLite 持久化、JSON 导入导出、导入校验。导入备份会替换当前数据，需要在界面确认，并暂停导入的计时器。
- 专注保护：在 **niri / Wayland** 上提供全屏锁定及应用白名单；每个项目可选配专属白名单，启用后在专注该项目的任务时替代通用白名单；保护中拒绝任务修改、暂停、重置和关闭窗口。可选严格模式禁止从应用内临时退出，到时自动解除；普通模式保留输入“结束专注”的提前退出。
- 定时锁机：独立的“小憩 / 定时锁机”页面，支持 1—720 分钟快速锁机、跨午夜的每周重复时段、时段列表可独立切换严格模式（编辑弹窗也可设置）。到点从托盘唤回全屏休息界面，睡眠不计入学习时长。规则默认不创建、不启用。

## 专注保护的适用范围

程序通过 niri IPC 获取前台窗口并把不允许的应用切回番茄 Todo。白名单按精确 `app_id` 匹配，可直接添加当前打开的应用。浏览器内的所有网站共用一个应用标识，因此允许浏览器也会允许其中的娱乐网站。

这是自律辅助功能。它不会结束其他进程，不会暂停或修改其他应用；无法阻止系统快捷键、工作区总览、其他显示器的内容或外部结束进程。严格模式由 Rust 拒绝提前退出，而非只隐藏按钮；IPC 故障仍会解除当前保护并报错。GNOME、KDE、其他 Wayland 合成器和 X11 上仍可使用任务与计时功能，但保护与锁机按钮会显示不可用。尚未实现云同步、在线自习室、网站过滤或操作系统级安全锁屏。

定时锁机需要应用保持运行，可收起到托盘并开启登录自启动。电脑休眠时不唤醒，恢复或重开应用时若仍在时段内则继续锁机。星期按开始日期计算，启用的时段不允许重叠。进入睡眠时结束当前专注并保留实际用时；锁机结束不会自动重启专注。

## 开发与验证

需要 Rust stable、Node.js 22.12+、pnpm、系统 GTK 3 / WebKitGTK 4.1 开发库、C 编译工具链和 pkg-config。

```sh
pnpm install
pnpm run desktop        # Tauri 桌面开发
pnpm run dev            # Rust 服务 + Vite 浏览器预览
pnpm run check          # TypeScript + Rust Clippy
pnpm run format:check   # rustfmt + Prettier 格式检查
pnpm test               # Rust 单元测试 + 构建 + 浏览器端到端测试
pnpm run desktop:deb    # 构建生产安装包
```

浏览器预览访问 `http://127.0.0.1:1420`，Rust 服务仅监听 `127.0.0.1:4319`。端到端测试使用独立临时数据库、4321 端口和 Chromium；可用 `CHROMIUM_PATH` 指定浏览器可执行文件。

原生保护测试：`pnpm run test:native`，需要 niri、Xvfb、tauri-driver、WebKitWebDriver、Python GObject/GTK。测试创建独立的嵌套桌面，验证白名单放行、非白名单回焦、拒绝关闭与暂停、全屏锁定和紧急恢复，不在用户当前桌面测试阻拦。

此测试入口构建内置界面的独立测试程序，无需另起 Vite；同时使用私有 D-Bus、临时 XDG 配置和 StatusNotifier 测试宿主，验证真实托盘菜单、隐藏后的计时、自启动开关、单实例恢复与无托盘时的回退。安装脚本验证：`pnpm run test:install`，使用临时用户目录检查配置保留、图标/启动项及重复安装。

验证入口覆盖 Rust 状态机、计划往返导入、模板预印与印刷防重、严格执行、跨午夜锁机，以及真实浏览器和独立嵌套 niri 桌面。生产程序加载内置界面，无需 Vite 服务。

持续集成在 Ubuntu 22.04 上运行 `pnpm run check`、`pnpm run format:check` 与 `pnpm test`；推送 `v*` 标签时由 [Release 工作流](.github/workflows/release.yml) 构建 `.deb` 与独立压缩包并发布到 Releases。

## 数据与实现

交换学习计划请使用 **偏好设置 → 学习计划 → 导入计划 / 导出计划**。字段和行为见 [学习计划文件标准](docs/PLAN_FORMAT.md)，配有 [JSON Schema](docs/plan.schema.json) 与 [通用示例](docs/plan.example.json)。导入按 ID 更新已有任务的配置（标题、日期、管辖、子步骤等）并保留进度与裁定；要整份替换、删除文件里没有的未完成任务，在文件里加 `"replace": true`。恢复完成进度和设置请用下方「数据与备份」。

给某个项目配置个性应用白名单时，可以先导出计划，把应用 ID 写进对应项目的 `appWhitelist`，再导入覆盖；例如告诉 AI「英语任务需要词典和浏览器」，由 AI 修改后回导即可。也可以在「专注保护」页选中项目，启用专属白名单后直接编辑；它只在应用白名单模式下、且专注该项目的任务时生效，并替代通用白名单。

[完整备份标准](docs/BACKUP_FORMAT.md) 及其 [Schema](docs/backup.schema.json)、[示例](docs/backup.example.json) 包含严格模式和定时锁机字段。恢复时暂停计时、清除当前锁机、停用导入的时段；规则和严格选项保留，需在本机重新启用。备份 v3 保留模板、印刷记录、节点裁定、配对与永久 ID 历史；旧版本备份不能直接导入。

桌面默认数据库为 `$XDG_DATA_HOME/studio.tomato.todo/tomato.sqlite3`，未设置时位于 `~/.local/share/studio.tomato.todo/`。`TOMATO_DATA_PATH` 可指定独立数据库。预览版使用 `artifacts/preview.sqlite3`，不会与正式版混用。不要在程序运行时手动修改 SQLite；迁移数据请使用界面内的 JSON 备份。

Rust 负责状态机、任务规则、数据校验、SQLite、统计和桌面保护；TypeScript 只负责视图、交互与本地声音。核心库由 Tauri 和 Axum 预览服务共享，避免预览与桌面产生两套业务逻辑。详见 [CODEMAP.md](CODEMAP.md)。字体 DM Sans 随应用打包，许可位于 `public/fonts/OFL.txt`。

用户提供的课表和私人备考分析位于忽略版本管理的 `artifacts/planning/`，不打入程序，也没有写入默认任务数据库。
