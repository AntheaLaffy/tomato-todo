## B. 可讲的细节

1. **为什么占用时段不锁机**：它的职责是「告诉排期器这段时间已经不空」，不是「禁止你做事」。把描述和管控分开，课表才能随便改而不影响判定结果。
2. **为什么要有「水课」这个字段**：真实的一周里，有些课的注意力成本和必修课完全不同。把它们标成可并行，排期才不会把一周算成 40 小时满课，也不会因为「有课」就自动放弃当天。
3. **为什么窗口要算上休息**：一个 4 番茄的任务中间必然要休息。如果只算专注时间，到点判定会提前触发；算上休息，提醒才落在真正该开始的那一刻。
4. **为什么宽限按分钟且当天有效**：它对应 README 里的「重修窗口」——迟到多久还算迟到。习惯是 0，因为这正是习惯的定义：到点不做就是缺勤。
5. **为什么提醒只在空闲时弹**：正在计时、正在锁机时弹提醒会打断节奏。设计上宁可延后，也不在你专注时抢屏幕——这条和第 2 期的保护逻辑联动。
6. **不滚动**：定时任务过了当天就不再提醒。相比之下，很多待办软件会一路滚下去，最后一屏全是过期的红色——这里选择让「漏了」这件事被明确记录，而不是被无限往后推。

## C. 机制（它怎么运转的）

这里有两个彼此独立的判定。占用时段回答「这段时间是不是已经被课表占住」：窗口由星期与起止时刻决定，跨午夜时结束时间顺延 1440 分钟。提醒回答「这条任务在它的计划窗口里该不该弹」：窗口等于专注次数乘单次时长，再加上次数之间的休息，最后加上宽限。两者只在诊断里相遇——把落在「需专心」时段内的计划块判成冲突。

## D. 语义规则与不变量

- 占用时段是描述性的：不锁机、不拥有进度、不参与完成度
- 只有「需专心」的时段参与冲突判定
- 提醒只在空闲时挂起（计时中、锁机中不弹）
- 定时任务过期即消耗，不滚动到明天
- 宽限只对普通任务生效；习惯为 0

## E. 边界与坑

- 占用时段**不锁机**：它不会阻止你在课上开别的应用。
- 冲突提示是**本地诊断**，不调用模型；它只指出重叠，不替你决定该删哪边。
- 提醒依赖应用运行；完全退出时不触发（可开托盘后台 / 自启动）。
- 宽限（重修窗口）只对普通任务有效；习惯 0、目标实例由阶段判定接管。
