## B. 可讲的细节

1. **为什么样式要分三层**：布局是每个组件的一次性决定，写成 inline style 最直接；hover、focus、选中、动画这些「状态」必须靠选择器，放 `ui.css.js`；颜色、间距、阴影这些跨组件常量放皮肤变量。三层各管一件事，页面就不会各自复制一份按钮样式。
2. **为什么对话框一定要挂到 `body`**：DSH 的内容列在可滚动容器里，内容列祖先的 `animation`（`fill-mode:both` 的 transform 关键帧）会成为 `position:fixed` 的包含块；不挂 body 时遮罩只盖住内容列、对话框落在页面中段偏下。没有 `react-dom` 的冒烟环境则退化为内联节点，而不是报错。
3. **为什么氛围要两层**：DSH 的 AppFrame 用不透明底色铺满视口，注入 body 的固定层会被整块盖住。地面层保留 SKIN.md 的结构（换宿主或壳层透明化时仍生效），天空层才是当前真正可见的那一版；两层共用同一份插画与微尘 markup，改作品只改一处。
4. **为什么主题用 `overrideTokens` 而不是注册主题**：注册主题会写用户的主题偏好、把跟随系统钉死成单一样式；`overrideTokens` 只提交浅/深两套值，跟随系统的行为不动，插件停用后 DSH 立刻恢复原貌。
5. **为什么按钮不用亮番茄做底**：白字压 `#d96d55` 只有 3.2:1，不到 AA；压 `#b9573f` 是 4.5:1。于是亮番茄退到图标、进度、链接这些非文字面，文字承载面用深一档的红。
6. **为什么看板娘不挡点击**：立绘是装饰，页面点击应当穿透；只有左侧那列 42px 头像片是 `pointer-events:auto`。触摸设备没有 hover，所以在 `@media (hover:none)` 下才把立绘放开成可点。
7. **为什么声音只给五个节点**：开始、暂停、完成、提醒是「需要抬头」的时刻；滚动、点击、勾选都不给声音。提示音是正弦短音、峰值远低于背景音，学习期间没有滴答声——注意力预算要花在刀刃上。
8. **为什么氛围存本机、背景板写设置**：氛围开关与时段是「这台设备上的观感」，换设备不该被同步；背景板是「这个人物陪着你」的数据语义，写进 `settings.personaBackdrop` 走 core 的 `saveSettings`，换设备一致。同一个设置行里两种偏好两种存法，是刻意的。
9. **为什么淡出必须够长**：噪声 BufferSource 在非零振幅处直接 `stop()` 会爆音，所以背景音切换与停止用 0.6s 线性淡出（代码注释要求 ≥500ms），淡完再断开节点。

## C. 机制（它怎么运转的）

界面没有独立的「皮肤引擎」：皮肤在插件 apply 时做三件事——注入一支样式表、往 body 插一个静态氛围层、向 `shell.overlay` 注册天空层，再把 DSH 的 `--dsw-*` 令牌换成纸色系。之后的观感全靠 CSS 变量与选择器：时段、氛围总开关、看板娘开关、低性能标记都写在 `html` 的 data 属性上，切换只改属性，不重绘 React 树。组件层的状态（hover、选中、弹窗入场、呼吸）同样由 CSS 类承担， React 只负责结构与 inline 布局。声音走另一条边：HUD 是唯一「永远挂载」的番茄状态组件，它把每张快照与前一张比较，只在状态跃迁时调用一次提示音，并把「背景音选择」同步给单例音频引擎；开关与音量来自设置，失败一律静默降级，不影响计时与任务。

## D. 语义规则与不变量

- 组件颜色取自 `--tomato-*` 与 `--dsw-alias-*` 变量；现有例外只有作品图形与沉浸层的深色实色（组件 CSS 的 `#fff` 勾选对勾、沉浸层的半透明白），改动这些要同时对照 `docs/SKIN.md` 的对比度约定。
- 所有动画必须在 `prefers-reduced-motion: reduce` 下停掉或退化为无动画；低性能设备只通过 `data-tomato-motion=lite` 降级，不逐帧判断。
- 对话框必须挂到 `document.body`；只有拿不到 `react-dom` 的冒烟/SSR 环境才允许退回内联渲染。
- 装饰层不得拦截交互：氛围层与看板娘立绘都是 `pointer-events:none`，只有切换列、HUD、沉浸层自己开启点击。
- 全应用只有一个 `AudioContext`、一条 master 增益：音量滑杆同时作用于背景音与关键节点音效。
- 背景音与音效共用 `settings.sound` 与 `soundVolume` 两个设置，不存在第二套独立开关。
- 皮肤偏好（氛围开关、时段）只存本机 `localStorage`，不随计划或备份导出；看板娘背景板相反，属于设置数据。
- 任何音频失败（无设备、被自动播放策略拦下、静音）都不得阻塞计时、任务或页面渲染。
- 沉浸模式里 Esc 只关对话框，不结束专注；退出全屏走右下角 minimize，结束本轮必须走确认对话框。

## E. 边界与坑

- `ToastHost` 的注释写「8s 自动消失」，代码是 3200ms；以代码为准，别按注释调时长。
- `docs/SKIN.md` 的集成点表还写着 `ctx.theme.register` 与 `<style id="tomato-skin">`，实际用的是 `overrideTokens` 与 `tomato-skin-style`；以本章 A 表第 1、10 条为准。
- 专注页滑杆是即改即存（400ms 防抖后 dispatch `saveSettings`），偏好页的分段音量要等「保存设置」才提交；两条路径写的是同一个字段，别以为其中一个没生效。
- 看板娘的显示完全取决于快照里的 `settings.personaBackdrop`；runtime 离线时设置行会置灰，这是显式的「不可用」而不是开关坏了。
- 地面层的微尘动画被 CSS 关掉了（`animation:none`）：它通常被 DSH 不透明底盖住，不做看不见的合成开销。
- 强制对比模式会隐藏整个氛围层，这是有意的：装饰不能干扰系统的高对比需求。
