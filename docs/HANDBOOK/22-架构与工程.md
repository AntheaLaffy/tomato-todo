## B. 可讲的细节

1. **为什么把领域核心抽成零依赖 TS**：规则（模板印刷、身份登记、保护、统计）要被 runtime 的 HTTP、MCP 与测试共用。核心不依赖 Node API，测试就能用 vitest 直接跑纯函数；runtime 只做「把 HTTP/MCP 请求翻译成 Action」的适配层，不在适配层重写规则。
2. **为什么 runtime 零运行时依赖**：它随 DSH 插件分发，用户不该为了一个插件去装一堆 npm 包。构建时把 core 打进 `vendor/core.mjs`，安装脚本只要保证 `bin/` 与 `vendor/` 是兄弟目录，运行时不需要 `node_modules`。
3. **为什么产物入库**：`runtime/vendor/core.mjs` 与 `plugin/client.js` 都提交进仓库，CI 与安装流程不必先跑构建。代价是改 core 或客户端源码后必须重跑脚本并提交产物，否则测试读到的还是旧文件。
4. **为什么客户端不用浏览器测试**：真实浏览器端到端依赖重、在 CI 里慢；冒烟用假 DOM 加真 React 渲染，能抓到工厂注册、slot 形状、渲染期 undefined 这类最常见的崩溃，剩下的交互留给用户与 DSH 冒烟。
5. **为什么 runtime 直接跑 `.ts`**：Node 24 的类型剥离让 `import "./engine.ts"` 在开发与测试时可用，省掉一层构建；但这也把 Node 版本变成硬前提，旧 Node 会在启动时报未知扩展名。
6. **为什么 CI 分两条 guard 线**：Linux 是唯一完整构建并真实运行 guard 的平台，所以 CI 在 ubuntu 上 `cargo build`；Windows/macOS 只做 `cargo check`，价值是尽早暴露 `#[cfg]` 分支的编译错误，而不是假装跨平台已验证。
7. **为什么生成器不进 CI**：规模数字与测试索引每天都会变，让 CI 重写它们只会制造无关 diff；CI 只跑校验，生成物由维护者在提交前重跑。
8. **为什么迁移工具放在 `scripts/`**：旧 SQLite 只读一次，属于一次性工程动作，不该进 runtime 的启动路径；把它留在脚本里，runtime 的数据入口就只剩 `plan.json` 与 `state.json`。

## C. 机制（它怎么运转的）

请求从 DSH 进入插件：client 半在面板里轮询 runtime 的本地 HTTP 读端点，写操作提交 Action；host 半通过 stdio MCP 或 subprocess 调 `tomato-runtime`，runtime 把动作交给 `@tomato/core` 的引擎，校验、保护、身份登记与落盘都由核心完成，适配层不重新实现规则。原生守卫是唯一离开 Node 的部分，它无域无状态，只按 runtime 的 HTTP 命令锁屏、放行白名单、发通知和聚焦窗口。工程上，core 与 runtime 各有独立测试入口，客户端用 esbuild 打成单文件并做无浏览器冒烟，guard 用 Cargo 测试加跨平台类型检查；CI 把这些入口串成一条线，发布则另由打包模板与 AUR 脚本处理。

## D. 语义规则与不变量

- 领域规则只存在于 `packages/core`，runtime 适配层与插件界面不得各写一份
- guard 无域无状态，锁定只活在进程内，崩溃后由 runtime 重发命令
- `runtime/vendor/core.mjs` 与 `plugin/client.js` 是生成物，只能由构建脚本产出
- 测试一律使用临时数据目录或内存数据，不碰用户正式数据
- runtime 测试不连接真实模型，助手对话与账号行为交给用户自测
- 插件界面不直接写数据，写操作必须经过 runtime 的 Action 与核心校验
- CI 只校验不改写生成物，生成物由维护者在提交前重跑

## E. 边界与坑

- Node 版本是硬前提：runtime 直接执行 TypeScript 源文件，Node 低于 22.6 会启动失败；开发文档写 22.12+，构建目标写 node24，三者要一起看。
- guard 的系统依赖只在 Linux 完整构建时暴露（`libxcb`、`glib2` 等），Windows/macOS 的 `cargo check` 不能代替原生运行验收。
- 客户端冒烟不是浏览器端到端：它验证渲染不崩，不验证真实点击、焦点、音效与 DSH 宿主行为。
- `release.yml` 仍是 Tauri 时代的发布步骤，与当前 runtime/guard 产物不一致；不要把 CI 的绿色当成发布可用。
- 版本号不统一：根包、core、runtime 是 0.13.0，插件包是 2.0.0；查版本时先说清是哪一个。
- CI 注释说 `--locked` 依赖根 `Cargo.lock`，仓库里实际只有 `crates/guard/Cargo.lock`；改变 guard 依赖时要提交的是这个锁文件。
