# 规则速查

> 手册章节 ｜ 最后核对：v0.9.8（2026-10-28）｜ 更新时机：改动类别推导、休息周期、计划块、提醒窗口、锁机重叠或保护强度时

把散在各章的规则写成可以直接引用的式子。记号沿用本手册约定：`x?` 表示可选、`[a,b)` 表示左闭右开区间、`⌈x⌉` 表示向上取整。每条规则后面给出实现位置与相关章节。

每条规则都有一个**规则 ID**（写在标题末尾，形如 `[rules.kind.derive]`）。其它章节引用规则时写 ID 而不是节号，这样调整本页顺序不会断链；ID 的写法与校验见 [00-读法与约定](00-读法与约定.md)。

## 1. 类别推导 `[rules.kind.derive]`

```
kind(task) =
    Habit     , 若 task.reminderTime 存在 且 (task.habitId 存在 或 task.recurring)
    Ordinary  , 其余
```

- 类别**不存储、不手填**，由字段推导；容器删掉后历史类别依然正确。
- 出处：`crates/core/src/lib.rs` 的 `Task::kind()`；详见 [13-任务与列表](13-任务与列表.md)。`[T]`

## 2. 计划块与提醒窗口 `[rules.window.pomodoro]`

```
计划块分钟 = 次数 × 单次时长 + Σ(第 i、i+1 次之间的休息)
其中 休息(i) = 长休息 , 若 i 是 longBreakEvery 的整数倍
             = 短休息 , 否则
次数 = max(estimate, 1)
```

- 提醒在 `开始时刻 ≤ 现在 < 计划块结束 + 宽限` 内有效；宽限只对普通任务生效，习惯为 0。
- 出处：`crates/core/src/reminders.rs` 的 `window_minutes()`；详见 [12-课表与提醒](12-课表与提醒.md)。`[T]`

## 2a. 当天休息周期 `[rules.timer.cycle.daily]`

```
当天番茄数 = count(session.completed 且 本地日期(session.endedAt) = 今天)
专注完成后的休息 = 长休息 , 若 当天番茄数 是 longBreakEvery 的整数倍
                 = 短休息 , 否则
```

- 同日跨任务累计、重启保留；跨午夜的专注归结束日，次日恢复的昨日完成仍归昨日。
- `session.completed` 包括到时完成与用户提前完成；实际秒数照实记录，两者都不自动勾选任务或步骤。
- 跨日不打断运行或暂停中的计时；新一天无完成记录时，昨日未开始的休息回专注待机。
- 出处：`crates/core/src/lib.rs` 的 `refresh_cycle()`、`tick()`、`tick_timer()`；详见 [13-任务与列表](13-任务与列表.md)。`[T]`

## 3. 上课时间（占用时段）的判定 `[rules.band.occupancy]`

```
band(block, date) =
    None                    , 若 date 的星期不在 block.days
    [start, end)            , 结束晚于开始
    [start, end + 1440)     , 跨午夜（end ≤ start）
```

- 只有「需专心」的时段参与冲突判定；「可以边听边写」的时段不报警——那里正是并行作业该待的地方。
- 出处：`crates/core/src/blocks.rs` 的 `band()`、`overlap_minutes()`，判定在 `diagnostics.rs`；详见 [12-课表与提醒](12-课表与提醒.md)。`[T]`

## 4. 定时锁机时段 `[rules.lock.schedule]`

```
归属星期 = 时段开始那一天的星期
时长     = (end - start + 1440) mod 1440
约束     = 启用的时段两两不重叠（把一周展开成 7 × 1440 分钟逐分钟占位）
```

- 判定「现在是否在锁机」时只看今天与昨天两天的时段（覆盖跨午夜）。
- 结束一次快速锁机只把抑制时间推到**当前时段末**，不影响后面无关的时段。
- 出处：`crates/core/src/lock.rs`；详见 [11-定时锁机](11-定时锁机.md)。`[T]`

## 6. 诊断阈值 `[rules.diag.thresholds]`

```
容量 = 用户填写的每日可用分钟
     ? 近 28 天中 ≥5 个活跃日（≥20 分钟）的中位数（下限 30）
     ? 每日番茄目标 × 单次专注

计划超量   : 剩余预计分钟 × 100 > 容量 × 130
安排过少   : （只看明天）有历史基线 且 明日非空 且 预计分钟 × 100 < 容量 × 30
投入下降   : 近期活跃日 ≥3 且 均值 < 历史基线 × 40%
习惯缺席   : 近 7 个完整日期中 安排 ≥4 次、缺席 ≥3 次 且 缺席占比 ≥50%
深夜记录   : 近 7 天中 ≥3 天有 23:00–06:00 结束的记录
```

- 全部为本地规则，**不调用模型、不自动裁定**；每条信号带证据与一个反问句。
- 出处：`crates/core/src/diagnostics.rs` 的 `diagnose()`；详见 [17-诊断与统计](17-诊断与统计.md)。`[T]`

## 7. 保护强度与严格模式 `[rules.guard.modes]`

```
允许(窗口) =
    True                      , 若 窗口.pid = 本程序 pid
    True                      , 若 protection.mode = off
    False                     , 若 protection.mode = lock
    窗口.appId ∈ whitelist     , 若 protection.mode = whitelist（精确匹配）

严格保护 = 存在 strict 的活动锁机
        或 (专注计时中 且 protection.mode ≠ off 且 protection.strict)
```

- 严格保护时后端拒绝一切提前结束与修改；非严格专注允许用户提前完成番茄或紧急退出，其余修改拒绝；休息锁机只允许紧急退出。
- 出处：`crates/core/src/guard.rs` 的 `allowed()`、`lib.rs` 的 `strict_protected()`；详见 [10-锁与专注保护](10-锁与专注保护.md)。`[T]`
