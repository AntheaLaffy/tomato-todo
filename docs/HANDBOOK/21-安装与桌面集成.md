## B. 可讲的细节

1. **为什么装进家目录**：不需要 root，不用包管理器权限，卸载就是按 manifest 删文件。对个人项目来说，这是最不容易得罪人的安装方式。
2. **为什么用 systemd user unit，而不是旧版 autostart `.desktop`**：runtime 与 guard 都是无界面的后台进程，systemd 提供 `daemon-reload`、`enable`、`disable` 的完整生命周期；autostart 入口是 GUI 时代的产物，现在没有桌面窗口可启动。
3. **为什么 guard unit 默认不 enable**：guard 由 runtime 监督并在崩溃后重启；两个 unit 各自 `Restart=` 会在 43988 端口上互相打架。unit 仅保留给手动或应急启动，`--enable-guard` 才显式交给 systemd。
4. **为什么用 manifest 而不是入口文件里的管理标记**：旧版靠 `.desktop` 里的 `X-Tomato-Todo-Managed=true` 认领文件；新版没有桌面入口，改成 manifest 记录全部已装路径，卸载和覆盖判断都只认这一份清单。
5. **为什么要原子写与整树替换**：写到一半的二进制或 unit 会让下一次启动直接坏掉；目录树如果只覆盖不替换，退役的旧文件会留下并在下一轮被读到，「退役」就变成假动作。
6. **`--dry-run` 的意义**：让用户在真正改动前看到「它要动哪几个文件、会执行哪几条 systemctl」，这是对系统级改动的尊重。
7. **为什么 `systemctl` 失败不判安装失败**：容器、最小发行版和没有用户会话的机器都可能没有可用的 systemd；文件已经装好，自启可以稍后手动 enable，没必要把整个安装判死。
8. **托盘能力随 Tauri 壳移除，但「关窗口继续计时」仍成立**：旧壳自己画托盘；现在常驻的是 DSH，DSH 没有系统托盘，关掉主视图不会停掉 runtime，计时与提醒照常。
9. **GNOME 扩展为什么只复制不启用**：扩展是桌面级能力，安装脚本不应该替用户打开一个会改变窗口行为的组件；复制完提示用户注销重登再手动启用，把决定权留在用户手里。

## C. 机制（它怎么运转的）

安装脚本把 runtime 与 guard 复制进用户目录，写两个 systemd user unit，默认只启用 runtime：它负责数据、HTTP API、MCP 与计时，guard 由 runtime 在需要时拉起并监督，因此不交给 systemd 常驻。每一条对外部文件的改动都有护栏：目标文件必须出现在旧 manifest 里才能覆盖，启动器软链必须恰好指向本程序；安装不再改桌面环境的配置文件，因此也没有需要先备份的第三方配置。目录树先拷到暂存再整体替换，二进制与 unit 用原子写，写坏的中间态不会留给下一次启动。桌面一侧的能力随平台不同：Linux 走 X11 或各家 Wayland 的 IPC，GNOME 与 KWin 需要可选的 Shell 扩展或脚本，Windows 用 Win32，macOS 没有宿主窗口因此只降级到白名单；可选扩展由独立脚本安装，只复制、不启用。

## D. 语义规则与不变量

- 不覆盖不在 manifest 里的文件，也不替换不指向本程序的启动器
- 安装与卸载只触碰 manifest 登记的路径，manifest 之外一律不动
- runtime unit 默认启用，guard unit 默认不启用，避免双重监督
- 整个安装与卸载过程不需要 root
- 安装过程不启用专注保护，GNOME 扩展也不自动启用
- 运行数据、guard token 与连接信息只写在用户目录，权限最小化

## E. 边界与坑

- 没有 systemd user 会话的环境（容器、部分最小发行版）只能装文件，自启要手动处理；脚本会警告但不失败。
- macOS 上全屏锁定不可用，guard 只能降级为白名单模式；这是平台能力缺口，不是配置问题。
- 其他 Wayland 桌面明确报不支持，不会偷偷退回 Xwayland 假装保护生效。
- 用户安装不再生成 `.desktop` 入口；`packaging/aur/tomato-todo.desktop` 是 Tauri 时代的残留，AUR `PKGBUILD` 并不安装它。
- 安装出的 runtime 直接执行 TypeScript，Node 过旧会在启动时抛 `ERR_UNKNOWN_FILE_EXTENSION`；unit 注释要求 ≥ 22.6，系统 node 版本要自己保证。
- `scripts/install.mjs` 打印的 `guardDataDir` 取的是 `XDG_STATE_HOME/studio.tomato.todo/guard`，而 `crates/guard/src/token.rs` 与 `runtime/src/guard-client.ts` 都用 `XDG_DATA_HOME`（默认 `~/.local/share`）；该值只出现在 plan 输出里，不影响 unit 与真实路径。
- 发布工作流仍是 Tauri 时代的步骤（`pnpm exec tauri build` 加上旧的 Tauri 安装脚本），与本章描述的安装形态不一致，不能据此认为各平台安装包已随重写产出。
