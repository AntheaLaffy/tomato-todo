## B. 可讲的细节

1. **为什么装进家目录**：不需要 root，不用包管理器权限，卸载就是删目录。对个人项目来说，这是最不容易得罪人的安装方式。
2. **三道护栏**：不覆盖别人的启动器、不接管没标记的桌面入口、改桌面栏配置前先备份。写这些代码的成本不高，但省掉的是「装完之后桌面出问题」这类最难排查的投诉。
3. **为什么助手目录要整体替换而不是合并**：如果只是覆盖，旧版本退役的技能文件会留在那里，下一轮助手还能读到——「退役」就变成了假动作。
4. **`--dry-run` 的意义**：让用户在真正改动前看到「它要动哪几个文件」，这是对系统级改动的尊重。
5. **托盘不是装饰**：关窗口继续计时、到点把窗口唤回来、锁机到点从托盘唤回全屏界面——这些都要求托盘常驻，所以它是功能的一部分，不是锦上添花。
6. **无托盘回退**：不是所有桌面环境都有托盘宿主，检测不到就走回退路径，而不是让应用起不来。

## C. 机制（它怎么运转的）

安装脚本把二进制与随包运行环境放进用户目录，写桌面入口与自启动项，可选地给桌面栏加一个固定入口。凡是涉及外部文件的改动都有护栏：不属于本程序的启动器与入口直接拒绝接管，改桌面栏配置之前先备份。助手运行环境用「先拷到暂存再改名」整体替换，而不是把文件合并进去。

## D. 语义规则与不变量

- 不覆盖不属于本程序的启动器与桌面入口
- 改动他人配置前先备份到安装备份目录
- 整个安装过程不需要 root
- 助手运行环境整体替换，退役文件不会残留
- 机器相关偏好留在 `desktop.json`，不随备份迁移

## E. 边界与坑

- Linux 需要系统有 GTK3 / WebKitGTK 4.1 运行库；`.deb` 路径适合 Debian/Ubuntu，其他发行版走 tar.gz + 脚本。
- `--pin-dms` 需要 DankMaterialShell 的 settings 与 session 文件存在，否则直接报错而不是猜。
- 登录自启动等机器相关偏好在 `desktop.json`，不随备份迁移。
- 卸载 = 删 `~/.local/lib/tomato-todo`、启动器软链、桌面入口三处（未做卸载脚本，可在视频里说明手动删除）。
