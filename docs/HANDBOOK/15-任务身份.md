## B. 可讲的细节

1. **删除仍保留身份**：旧专注历史可能引用已经删掉的任务。保留 ID 可以避免新任务继承旧历史。
2. **恢复需要原始内容**：撤销是找回同一实体，不能借恢复入口把一个旧 ID 用在任意新任务上。
3. **步骤使用局部编号**：步骤只在所属任务内寻址；它不是独立实体，不占用全局身份登记。
4. **本地转换与交换文件分开**：本地数据库可以明确识别旧结构并一次性转换；交换文件需要满足当前契约，避免旧配置被静默忽略。

## C. 机制（它怎么运转的）

动作先在候选状态执行，再合并前后身份历史。消失的实体标为 retired，新出现实体不得复用已退役 ID。任务删除时留下恢复内容；撤销通过同一核心预检核对内容，再恢复原实体。候选状态校验成功才写入数据库，失败不会改变当前状态。本地旧版数据则在打开数据库时先移除退役类型、转换任务和恢复记录，再进入相同的身份核对与完整校验流程。

## D. 语义规则与不变量

- 不同类型也不能共用 ID；删除不回收 ID。
- 计划导入不允许复用历史 ID，备份合并本机身份历史。
- 子步骤编号是局部编号，不属于独立实体登记。
- 恢复内容必须与登记的原任务一致；候选动作校验失败不写入。

## E. 边界与坑

本地数据库转换只用于 v3 到 v4。外部文件按当前格式校验，不能借旧备份或新计划绕过身份限制。
