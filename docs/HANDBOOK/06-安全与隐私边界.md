## B. 可讲的细节

1. **信任边界是「谁在执行」而不是「哪个功能」**：任务、统计、设置全在本机；只有助手被真正使用时，分析所需的上下文才会发给所选模型服务。这条边界写在文档里，也写在默认关闭的开关上。
2. **权限位写在代码里而不是靠安装脚本**：私家目录 0700、敏感文件 0600 由创建路径的代码保证，无论是桌面、预览还是测试启动都一致——安装脚本会被人换掉，代码不会。
3. **原子写与权限是一件事**：先把临时文件写成 0600 再改名替换，既有权限也有原子性；否则可能出现「文件已存在但权限还没收紧」的窗口。
4. **为什么会给私网拦截开一个口子**：`198.18.0.0/15` 在 RFC 里是基准测试段，但 Clash 一类透明代理会用它承载公网域名。若照本宣科地拦，用户所有联网工具都会失灵，而且报错看起来跟代理无关。这是一个「宁可放宽、也不静默失效」的取舍，注释写得比规则还长。
5. **备份故意不含凭据**：备份会被拷到 U 盘、网盘、另一台机器上。把密钥放进去等于把凭据的传播路径交给用户的一个顺手操作。
6. **桥接的认证是「本机 + 令牌 + 来源」三重**：仅监听回环地址、要求连接令牌、再拒绝浏览器来源。三者只要少一条，本机上的任意网页就可能驱动你的数据。
7. **外部服务器的风险被明说**：MCP 服务器以你的身份在沙箱之外运行，等价于你亲自运行那个程序——所以助手只有在用户明确要求时才去改 `mcp.json`。

## C. 机制（它怎么运转的）

数据分成三类，处理方式完全不同。第一类是**业务数据**：任务、统计、设置、备份，它们只在本机流动，从不联网。第二类是**凭据**：模型密钥与 OAuth 令牌，它们被限制在一个 0700 的目录里、以 0600 落盘，既不进日志也不进备份，也不出现在任何给界面读的状态接口里。第三类是**发给模型的上下文**：只有当助手这一轮真的在分析时，所需的那部分学情才会离开本机，去往用户自己配置的那个服务。网络出口被压到极小：除了模型与检索的几个域名，代码不做任何对外请求；网页读取这一条路则被限制成「公开、无凭据、标准端口、非私网地址」。对外提供服务时反过来做三重认证——只监听回环、要求令牌、拒绝浏览器来源。

## D. 语义规则与不变量

- 助手私有目录 0700、其中敏感文件 0600，写入必须原子（临时文件 + rename）
- 凭据不得出现在状态接口、日志与任何备份文件中
- 对外请求只允许公开 http(s)：无认证信息、标准端口、地址不属于私网/保留段（`198.18.0.0/15` 例外）
- MCP 桥接仅监听回环、要求连接令牌、拒绝浏览器来源；不启动第二份数据库
- 应用本体无账号、无遥测；联网只发生在助手被使用且用户已配置凭据时
- 助手的沙箱档位都不提权；外部 MCP 服务器始终在沙箱之外以用户身份运行

## E. 边界与坑

- 这是**文件系统权限层面的保护**，不是加密存储：同机器上有你身份的进程仍可能读到这些文件。
- 发给模型的上下文由用户选择的供应商处理，本项目不控制对方的留存策略。
- 外部 MCP 服务器是第三方程序，它的行为与风险不在本项目的管控范围内（这一点在工具描述里明说）。
- 外部 MCP 客户端不能执行紧急退出；严格保护与不可逆裁定照旧生效。
