# 实现手册（HANDBOOK）

> 这本手册回答一个问题：**这个软件到底是怎么运作的**。
> 它按域切开、每章独立成篇，事实以当前代码为准并标出出处，面向**要读这份代码的人**（贡献者、审核者、未来的自己），而不是面向观众。
> 与 [CODEMAP](../../CODEMAP.md) 的分工：CODEMAP 说改一处要动哪些文件，本手册说那些文件里的实现是什么；对照表在 [04-导航对照](04-导航对照.md)。
>
> 最后核对：v0.10.0（2026-10-28）｜ 维护方式：改代码就改手册，见文末约定。

## 与既有文档的分工

| 文档 | 回答什么 | 不该在这里找什么 |
| --- | --- | --- |
| [../DESIGN.md](../DESIGN.md) | **为什么这样设计**：任务/习惯/项目/愿景的划分、模板印刷的取舍 | 具体函数、阈值、字段上限 |
| [../PLAN_FORMAT.md](../PLAN_FORMAT.md) / [../BACKUP_FORMAT.md](../BACKUP_FORMAT.md) | **文件契约**：字段、范围、导入导出语义 | 为什么这么定 |
| [../AGENT.md](../AGENT.md) | 学习助手的**设计与权限** | 各域的实现细节 |
| **本手册** | **实现事实与边界**：按域列出「它做什么、怎么做的、做不到什么」 | 面向用户的上手说明（看 [README](../../README.md)） |

一句话：`DESIGN` 讲取舍，`*_FORMAT` 讲契约，`AGENT` 讲助手，**本手册讲实现事实**——同时也是对外表达（视频、文章、答疑）的取料处。

## 每章的六段结构

| 段 | 内容 | 怎么用 |
| --- | --- | --- |
| **A. 事实** | 逐条列实现事实，每条带代码出处（文件:函数/行） | 想确认「到底是不是这样」时先看这里 |
| **B. 可讲的细节** | 每条回答「为什么这么设计」 | 讲给别人听、写文章时的论点 |
| **C. 表达素材** | 已经翻译成白话的段落 | 直接念、直接抄；这里出现仓库黑话算违规（有检查脚本） |
| **D. 可复现的画面** | 截图路径与录屏脚本 | 做视频/演示/答疑配图 |
| **E. 边界与坑** | 做不到什么、容易误解什么 | 对外表达时必须一起说，避免过度承诺 |
| **F. 待补与更新点** | 还没核对到的、需要跑起来才能确认的 | 汇总在 [90-待补清单.md](90-待补清单.md) |

## 维护约定

1. **改代码就改手册**：动了某章涉及的实现，先更新那一章的 A 表与 B 段，再同步其他文档。
2. **页眉跟着版本走**：核对完一章，把页眉的「最后核对」改成当前版本与日期——检查脚本会强制这一行存在。
3. **两条自查都要过**：

   ```sh
   python3 scripts/check-handbook.py        # 手册：结构、页眉、出处、措辞、隐私
   python3 scripts/handbook-backlog.py      # 重新汇总 90-待补清单.md
   python3 scripts/handbook-stats.py        # 重新采集 01-规模盘点.md 的规模数字
   python3 scripts/handbook-paths.py        # 重建各章 C/D 段（阅读顺序、关键符号、调用链）
   python3 scripts/handbook-tests.py        # 重新采集 95-测试索引.md 的测试清单
   ```

   `pnpm run check:handbook` 一次跑完这四条；单跑某一条用 `pnpm run handbook:stats` / `handbook:tests` / `handbook:paths`（入口句与调用链改 `scripts/handbook-paths.py` 的 `ENTRY` / `CHAINS`，然后重跑）。

4. **生成物不要手改**：`pnpm run check:handbook` 会重写 [01-规模盘点](01-规模盘点.md)、[90-待补清单](90-待补清单.md)、[95-测试索引](95-测试索引.md) 三份文件——提交前跑一次，让它们与代码一致；CI 只跑 `scripts/check-handbook.py`（纯校验，不改文件），否则每次代码改动都会因为行数变化把无关 PR 变红。
5. **措辞可对外**：C 段里不许出现仓库黑话（脚本会查），也不许出现任何私人任务、私人系统的字样。
6. **引用数字要标版本**：例如「随包技能 10 个」这种数字会随版本变，写的时候注明版本。
7. **新增一章**：复制下面的空壳，编号接在现有序列后，并把它加进上面的覆盖表。

```md
# 域：<一句话说清这一章讲什么>

> 手册章节 ｜ 最后核对：v0.10.0（2026-10-28）｜ 更新时机：<什么改动会触发更新>

**期数**：<如果这一章也用作视频材料，写清期数>
**一句话卖点**：<对外一句话>
**读者会问的第一个问题**：<问题>

## A. 事实（每条带代码出处）
## B. 可讲的细节（每条回答「为什么」）
## C. 表达素材
## D. 可复现的画面
## E. 边界与坑
## F. 待补与更新点
```

## 与视频物料的关系

- 手册是**代码参考手册**：面向读代码的人，随代码更新、入库、评审、追责。讲稿与镜头不进这里。
- 视频物料是**一次性产物**：成品文案、分镜、截图脚本都在 `artifacts/publish/`（不入库），需要时从手册取料。
- 已有成片文案：`artifacts/publish/bilibili-番茄Todo-第一期推广片.md`（推广片）、`artifacts/publish/30-第02期分镜-锁与专注保护.md`（第 2 期）。
- 真实界面截图由 `artifacts/publish/shots.mjs` 生成到 `artifacts/publish/shots/`，手册的 D 段直接引用这些文件。
