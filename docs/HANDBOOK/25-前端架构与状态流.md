## B. 可讲的细节

1. **为什么入口只有一个工厂**：DSH 的客户端半只认一个 `__ModuleLoader__.load`，脚本执行时不能有别的副作用；源码按职责分模块、构建时收成一个 IIFE。模块顶层只做「注册」这类幂等动作（文案表、页面注册），注入样式、起轮询、挂 slot 都留到 `apply`，这样插件被停用/重挂时还能干净地重来。
2. **为什么 React 用活绑定而不是参数传递**：几十个组件模块都从 `runtime.js` 拿 `h`/`useState`，如果每个组件都要接一个 `react` 参数，签名会被污染。`installRuntime()` 在 `apply` 之前完成，之后这些 `let` 绑定一直有效，ESM 的 live binding 足以让打包后的代码正常工作。
3. **为什么状态只留一份**：九个页面共享任务、统计、导航计数，任何页面改完都必须立刻反映到别处。把快照放在模块级单例，页面只订阅，就不可能出现两份互相覆盖的数据。
4. **为什么轮询要自适应**：大快照（任务、课时、教育数据）的解析成本远高于一次本地心跳。专注中 5s、空闲 8s 是折中；秒级走字由心跳加 `deadline` 插值完成，不必每秒请求。
5. **为什么跨树导航用模块信号**：主视图在 `main` 槽位、沉浸层在 `shell.overlay`，React 树不同，props 传不过去。模块级的「当前页 + 订阅者」是两者之间最小的桥。
6. **为什么页面自注册**：加一页只改自己的文件，框架不用动；代价是注册表是隐式的，排查「页面为什么没出现」要先确认 `pages/index.js` 是否 import 了它。
7. **为什么偏好页要草稿**：设置字段多、校验是整份的，边改边存会出现「一半新一半旧」的中间态。草稿 + 显式保存把提交点收成一个。
8. **为什么全屏接管不设 z-index**：DSH 的 `shell.overlay` 有自己的层级，HUD、提醒、沉浸层都在那之上；主视图只是个铺满视口的 `fixed` 容器，设了 z-index 反而会把该在上面的浮层压下去。

## C. 机制（它怎么运转的）

插件被 DSH 激活时，工厂先安装 React，再注册皮肤（样式表、氛围层、主题令牌、品牌位、设置行），最后注册应用（启动 store 轮询、绑定面板打开器、往主视图、`shell.overlay` 的三处、输入框入口与侧栏底部挂组件）。应用的所有数据都来自 store 里的同一张快照：`dispatch` 把动作 POST 给本机 runtime，响应带回新快照后立即替换并广播，所有 `useSnapshot` 组件重渲染；另有自适应轮询捕捉内核自己产生的变化（自动切换、提醒、外部写入）。页面由注册表按 order 排列，点击导航只是写模块级的当前页并持久化到 localStorage；跨树的沉浸层与 HUD 通过同一套模块信号切页。偏好页在本地保留草稿，脏时不跟随快照，保存时把整份设置一次性交给 runtime 校验。构建把入口打成一个 IIFE 产物，冒烟在没有浏览器的假 DOM 里把真产物跑一遍，保证「装得上、渲染得出、dispose 不抛错」。

## D. 语义规则与不变量

- 界面不缓存第二份业务状态：所有页面都从 store 的同一张快照派生显示。
- 写操作只走 `dispatch()`（POST `/api/dispatch`）；不允许组件自行改内存状态后「稍后同步」。
- 读失败只更新 `readError` 并保留旧快照，不清空界面、不伪造数据。
- 页面切换只认 navigation 的模块信号与 `localStorage`；组件不得各自维护一份「当前可见页」。
- 主视图与 `shell.overlay` 不在同一 React 树，跨树交互必须走模块级信号，不能靠 props 硬穿。
- `plugin/client.js` 是构建产物：只能由 `pnpm build:client` 生成，源码改动一律落在 `plugin/src/client/**`。
- 插件 dispose 时必须停轮询、清订阅，并由 `ctx.effect` 移除样式、氛围层与主题覆盖。
- 需要跨重绘存活的浮层（对话框）挂 `document.body`；拿不到 `react-dom` 时退化为内联渲染而不是报错。

## E. 边界与坑

- 轮询与动作并发时没有 revision 比较：`inflightRead` 只合并并发读，动作响应直接覆盖快照。改这里时若要让「过期轮询回复」失效，需要显式记 revision，不能假设现有代码会挡住。
- `store.js` 里的 `MUTATING` 集合记录了正在提交的动作名，但没有任何读取方——旧版的单飞守卫已经不在了；不要以为它会拒绝并发动作。
- `API_BASE` 写死 `127.0.0.1:43987`，没有配置入口；改端口要同时改这里与 runtime。
- 页面内容容器的 `key` 是页面 id：切换页面会重挂，快照变化只重渲染、不重挂——所以页面内部状态（对话框、草稿）能跨轮询保留，但偏好页仍用 `dirty` 显式挡住快照覆盖。
- `docs/SKIN.md` 第 0 节的集成点表把侧栏入口写成 `sidebar.panellist`、主题写成 `register`；实际代码是 `sidebar.brand.mark`/`sidebar.brand.name` 加 `overrideTokens`（以 A 表第 6、7 条为准）。
- 冒烟用假 DOM，滚动、动画、真实 portal、`AudioContext` 这些浏览器行为都覆盖不到；`pnpm check:client` 只保证「能渲染、注册齐全、dispose 不抛错」。
- `window.__tomatoDsh` 只在 `window.__TOMATO_TEST__` 置位时出现，生产控制台里没有，别把排查脚本当契约。
- 心跳只在计时运行时 emit；空闲时 HUD/页面上的时钟类数字不会每秒刷新，这是设计而不是掉帧。
- 语言只认 DSH locale id，插件不另存语言偏好；`zh*`/`ja*` 之外一律回退英文，改语言必须走 DSH 设置持久化。
- 作业草稿只是把记录 ID 交给学习助手，不会替用户提交、批改或订正；DSH 输入框不可用时只弹提示，不假装已写入。
