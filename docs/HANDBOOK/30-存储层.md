## B. 可讲的细节

1. **为什么拆两个文件**：`plan.json` 是域数据的唯一来源，也是人可读、可导出的那一份；`state.json` 装每秒都可能变动的计时、提醒与教学状态。分开之后，查看与排查计划不必翻整库，频繁写入也不会把整份计划重新缩进一遍。
2. **代价是两文件可能短暂不同步**：两次 `rename` 之间崩溃，磁盘上会出现新旧混合的一对文件。读取时会重新校验；两份文件若互相矛盾，宁可加载失败并保留原文件，也不会替用户合成一份「看起来合理」的新状态。它不是事务，不能当成数据库用。
3. **为什么用临时文件加 `rename`**：`rename` 在同目录内是原子的，读者要么看到旧文件要么看到新文件，不会读到写了一半的 JSON。加上 `fsync` 是为了让「已经写成功」在断电后仍然成立。
4. **为什么 `state.json` 不缩进**：它不给人读，只给 runtime 读；导入教学记录后可能有几 MB，每秒写一次时缩进与空格是纯粹的浪费。`plan.json` 反过来，缩进是给人排查用的。
5. **为什么坏数据不覆盖**：读不出来就报错、保留原文件，用户至少还能把文件拿去求助。若用默认数据覆盖，事故就变成不可逆的。
6. **为什么预检与执行同一条路径**：如果审阅另写一套检查，它会和真实执行慢慢漂移——用户看到「审阅通过」，应用却失败，或更糟：通过但产生了不同的结果。共用 `previewAction` 让这句话在代码层成立。
7. **为什么装载时也要重建身份登记并落盘一次**：身份历史可以从数据推导。打开时补齐并写回，后续每次动作就不必处理「少了登记」这种历史遗留状态。
8. **为什么 token 要跨重启保持稳定**：`connection.json` 同时被 `--mcp` 桥接和外部 MCP 客户端读取；每次重启都换 token 会让已经保存的客户端配置失效，所以 `loadOrCreateConnection()` 优先复用旧值，只在缺失时生成。
9. **为什么没有跨进程锁**：单机单用户的默认形态是一个 runtime 进程，文件锁会把实现复杂度抬高一整层。代价是共享数据目录时必须自己保证只有一个写者，端口冲突只是默认配置下的提醒，不是保护。

## C. 机制（它怎么运转的）

启动时先确保数据目录存在，再分别读 `plan.json` 与 `state.json`，把计划、设置、计时、历史、身份、锁机与教学记录拼成一份 `AppData`；缺文件就给默认值，文件坏了就报错并保留原文件。拼好的数据交给核心引擎，克隆、重建身份登记、整体校验之后先用调用方的 `save` 写回一次，保证磁盘上的内容与内存模型一致。此后的每一次动作都遵循同一节奏：克隆当前状态、应用动作、校验教学转移、重建派生登记、再验身份，全部通过才落盘；每秒的计时推进只在真的产生变化时写。落盘时两份文本先算好，再各自用临时文件加 `fsync` 与 `rename` 原子替换。连接信息、guard token 与导出文件都放在同一数据目录下，分别由连接模块、guard 客户端与导出路径管理。

## D. 语义规则与不变量

- `plan.json` 是计划数据的唯一来源，`state.json` 只放运行状态，两者合并后必须能重新解析与校验
- 每次落盘都是整份替换，不存在写了一半的 JSON
- 只有通过预检（应用动作、教学转移、重建登记、整体校验）的状态才允许落盘
- 解析失败不得覆盖原数据：报错并保留原文件
- 同一数据目录只允许一个 runtime 写者；跨进程并发没有文件锁兜底
- guard token 与连接 token 只写在用户数据目录，token 文件权限 0600，服务只监听 127.0.0.1
- 计划、备份与内部模型是三层版本号，不能互相代替

## E. 边界与坑

- 两个文件不是事务：`writeDataFiles()` 先写 `plan.json` 再写 `state.json`，两次 `rename` 之间崩溃会留下短暂不一致；重启时会重新校验，矛盾时宁可报错保留原文件，也不会自动合成一份新状态。
- `state.json` 不缩进、也不带版本字段；手工查看容易误读，升级判断只能看 `plan.json` 与备份版本。
- 核心 `Engine.open()` 的 `writeAtomic` 用固定 `<path>.tmp` 且不 `fsync`，只在单文件存储路径使用；runtime 实际走 `writeDataFiles()`，不要把它当成 runtime 的落盘实现。
- 运行时不要手改数据目录里的文件（README 明确写了）；要改数据走导出、编辑、再应用，或走工具脚本。
- `agent/connection.json` 不是原子写：写入瞬间崩溃可能留下半个 JSON，但读取失败会回落到「重新生成」，不会阻止启动。
- 数据目录可以用 `--data` 指定，但连接信息与 guard token 都按数据目录解析；换目录等于换一份 runtime 身份，旧目录的 token 不会被复用。
- 旧 SQLite 的 `-wal`/`-shm` 文件不再被 runtime 使用；迁移脚本只读库，不写库，建议先完全退出旧应用。
