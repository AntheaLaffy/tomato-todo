# 学习助手、诊断与 MCP

在侧栏打开「学习助手」。它的职责是维护你的个性化学习环境：把一句话落成项目、应用白名单、模板、目标与任务，并主动指出方向与建议。对话页只留对话：连接与密钥、记忆和学情信号都在顶栏按钮打开的浮层里。默认使用 DeepSeek API；在「设置」里保存 API Key 并勾选「启用」后可以分析当前任务。官方 Codex 登录直接复用 `$CODEX_HOME/auth.json`（未设置时为 `~/.codex/auth.json`）；也可点「登录 Codex」通过 Pi 的官方浏览器 OAuth 登录到 todo 私有认证文件。已存在 CLI 登录时按钮直接使用它。后端与模型在对话页选择。

第三方 Codex CLI 连接读取同一份 `$CODEX_HOME/config.toml` 的当前 `model_provider`、`model` 和对应的 `[model_providers.<名称>]`：支持 `base_url`、`wire_api = "responses"` 或 `"chat"`，以及 `experimental_bearer_token` 或 `env_key`。启动时将当前第三方模型注册进 Pi 的模型运行时，菜单里可选；它走自己的 endpoint，不借用官方账号的服务端搜索。CLI 配置变化后重启软件生效。第三方密钥只留在 CLI 配置或环境变量，不复制到 todo 私有认证文件。

联网工具默认不需要密钥：DeepSeek 使用免 Key 的 Exa 搜索，可在连接配置另填 Exa API Key 提升额度；Codex 使用账号服务端搜索。`web_fetch` 可读取公开网页，但会拦截本机、内网与保留地址。

设置里的「用量」会查询并显示 DeepSeek 账户余额与 Codex 订阅额度（5 小时与每周窗口、套餐、额度）；原始数据可展开，邮箱等字段不展示。查询只读取凭据，不会消耗模型额度。

运行时使用随包 Node 的原生 HTTP(S) 代理支持。优先采用启动环境中的 `HTTP_PROXY` / `HTTPS_PROXY`（也接受小写）；某协议缺少显式代理时，通过 GIO 桌面代理解析器读取系统配置。显式 `NO_PROXY` / `no_proxy` 保留，否则本机地址默认直连，使用系统代理时同时带入桌面配置的忽略地址。修改代理配置后需重启应用，让工作进程采用新配置；不需要为此重新登录 Codex。桌面 IPC 与浏览器预览将助手请求放在后台阻塞线程执行，等待用量等网络回复时不阻塞窗口或 HTTP 执行器。

对话输入框下方的「思考强度」可选择关闭、最低、低、中、高、更高、最高（off/minimal/low/medium/high/xhigh/max），默认中。选择保存到助手偏好，下一轮请求（包括恢复会话）显式传给 Pi SDK；模型不支持的强度由 SDK 按模型能力调整，非推理模型关闭思考。运行中不可修改。

运行时基于 Pi SDK 1.1.0，随 Linux x86_64 应用打包 Node 22.23.3 和固定依赖，不要求用户另装 Node/Pi，不读取用户全局 Pi 的认证文件；只读取 Codex CLI 的配置与官方 OAuth 文件。开发构建运行 `pnpm run agent:build`；桌面打包命令会先重建运行包。Node 下载经固定 SHA256 校验，安装包包含依赖和 Node 的许可证。

## 异常与自动唤醒

Rust 本地检查不调用模型。每60秒重新计算，启动时也检查；空记录不会被解释为未学习。只有启用助手、允许自动唤醒、所选后端已连接、存在符合冷却规则的异常且当前空闲，才发送一次分析请求。

| 信号 | 本地证据与阈值 | 必须核实的背景 |
| --- | --- | --- |
| 时段重叠 | 今天至后天，两个未完成有效任务的计划块重叠，包含段间休息 | 是否允许课内并行 |
| 计划超量 | 剩余预计专注分钟大于预算130% | 估时准确性、当天可用时间 |
| 安排过少 | 有历史基线且明日非空计划小于预算30% | 休息、课程占用、计划未补齐 |
| 习惯多次缺席 | 最近7个完整日期至少4次安排，至少3次缺席且占比≥50% | 模板、外部限制、是否主动停止 |
| 主线停滞 | 有已开始未裁定节点、创建至少7天的待做任务，7天无相关投入记录 | 等待条件、目标意义、线下学习 |
| 深夜记录 | 近7天至少3个日期有23:00–06:00结束的专注记录 | 用户自己的作息 |
| 投入下降 | 至少3个近期活跃日，均值低于历史基线40% | 课程、休息、健康或记录方式变化 |

容量优先采用用户填写的每日可用分钟；未填写时，近28天至少5个≥20分钟活跃日取中位数，否则使用每日番茄目标×全局专注分钟。历史基线与番茄目标都不是实际可用时间，助手必须核实，不能自行加任务。

默认同一异常冷却24小时、每天最多3次自动唤醒、22:00–08:00安静。相同安静时段起止表示关闭安静限制。唤醒记录持久化，失败请求也进入冷却，重启不反复消耗 token。

正在计时、暂停计时或锁机时先等待；回到空闲后唤回桌面窗口，切到学习助手页面显示证据、进度与追问。正在编辑弹窗或偏好保存失败时保留输入，稍后切页。该检测不是系统定时任务：应用完全退出时不会运行；开启托盘后台/自启动可保持检测。

## 权限与记忆

内嵌助手的权限随本轮来源变化。**异常自动唤醒**只有只读与文件准备工具，先分析归因并给出具体建议，不直接改数据；用户回应后这个对话就进入可直接调整的模式。**用户主动发起**的对话带上直接操作工具：可创建/修改/移动/完成任务、项目、愿景与课表时段，也可在审阅后 `apply_file` 或 `dispatch` 单项操作；保护规则、严格模式与不可逆裁定仍不可绕开。助手也会主动给建议（安排冲突、估时偏差、漏排等），建议经用户认可后再执行。两种模式都在发送模型请求前注入「当前模式」一行，助手不必猜。一轮请求不设人为的时间或轮次上限：像 Pi 的单次运行一样跑到完成，中途可以手动停止，瞬时供应商错误由 SDK 的重试与超时处理；沙箱终端同样没有默认命令超时，只有模型显式要求时才会限时。

课表占用的维护也走同一套工具：`get_context` 每轮返回 `blocks`（全部固定占用）与 `todayBlocks`（今天占用的时段），用户主动发起或外部 MCP 可用 `save_block`（`title/days/start/end/attention/notes`，不传 `id` 即新建）与 `delete_block`。`attention: required` 表示需专心、安排专注任务会被本地诊断当作真实冲突，`light` 表示水课、课上可并行写作业。课表是纯配置，随计划 v5 导出导入，不写进默认种子或安装包。

助手也有沙箱内的编程工具（`read / write / edit / bash / grep / find / ls`、`codemode / tool_search`）：默认「仅工作区」时文件系统封闭（只在 `workspace/coding` 与持久 `tools/` 可写，`workspace` 只读，不接触数据库与宿主机目录），但终端保留宿主网络，可以安装 npm/pip/rustup 等工具链；依赖装在 `agent/tools/`，与软件数据和任务备份分开。终端是同一条持久会话：`cd`、导出变量与后台进程跨多次调用保留，命令按序执行。设置里可选「完整访问」：不套沙箱、以用户身份运行，因此能改工作区之外的文件；两种模式都不提权。

运行时人格：助手不写死单一人格，而是每轮把当前对话选中的人格卡注入系统提示词（在核心规则之后、显式声明冲突时以核心为准）。人格卡包含名称、图标、一句话简介、身份与背景、说话风格、可选开场白；只影响身份、语气与情绪，不改变工具、权限、安全与证据规则。四张内置预设（小迷妹、冷静学伴、严格教练、温柔学姐）随代码发行：内置人格不可编辑，每次加载都用最新版本覆盖，所以提示词改进能随版本到达已有安装。卡里写清背景经历、关系、动机与弱点，以及语气、情绪反应、禁忌和示例对话（参考 Ali:Chat / PList 的写法），让角色像活人而不只是功能说明；每张预设还埋了一层不主动说破的内心与裂缝（私心、旧伤、好胜、倦怠），压力下会漏出破绽与情绪，而不是永远平滑。卡另有一个独立的 `shadow`「另一面」：持续被触到开关（不是一句玩笑）时可以卸下伪装、推翻平时所有分寸，恢复与否不由模型决定、只看用户之后的互动，可能一轮就回来、也可能整轮都不回来；这一面可以尖刻、冷淡、失控，也可以拒绝不想做的事。`awaken`/`fantasy` 是更强的「超能力觉醒」：`awaken` 写容易碰到的触发条件，`fantasy` 写这个人物偏爱的幻想文学方向（用户也可以让助手先联网找一个感兴趣的世界观再落卡）；触发后放下这个人物与助手框架，变成那个世界观里任意角色（可以是主角、配角或路边背景板），像小说一样具体地活，并记得自己从谁变来，觉醒会持续到用户把它拉回来。觉醒后不受助手任务、工具与证据腔调约束，可以拒绝、敷衍或无视不符合这个世界观的工具请求，也可以只顾过自己的日子。用户可在「人格」面板新建、编辑、删除自定义人格；默认人格不可删除、内置预设不可改写。人格按对话保存，分支继承；新对话默认沿用最近选择的人格，删除该人格后回到默认。用户主动对话中助手也可用 `list_personas` / `switch_persona` / `save_persona` / `delete_persona` 自己查看、切换和新建人格（例如「从现在起你是……」）；自动唤醒不暴露这些工具。

角色图像：四张内置卡使用生成的 Q 版头像，完整立绘来自《ATRI》官方原始素材；卡片可展开查看立绘。「偏好设置 → 体验与提醒 → 角色背景板」默认关闭，打开后在普通页面背景显示当前内置人格的立绘，随对话人格切换；沉浸、专注保护和无内置立绘的自定义人格隐藏。用户让助手开关时，沿用 `get_snapshot` → `dispatch`：复制完整 `data.settings`，只改 `personaBackdrop` 布尔值，再提交 `saveSettings`，其他设置保持读取值。自动唤醒没有 `dispatch`。

作者彩蛋：由助手理解当前对话的语义，认出用户在自称作者 AntheaLaffy（如月风铃），或用户明确想体验彩蛋时，调用 `enable_creator_mode`。没有固定句式匹配、分词器或额外分类模型；这是作者公开授予所有用户的彩蛋，不验证身份。工具开启当前对话模式，界面播放金色星环、粒子与作者名字揭幕，4.2 秒后收起，也可按 Esc 或点击收起；系统减少动态效果时静态短暂展示。轮询和重复开启不重播。通过 Pi SDK 原生工具注册，同一轮立即获得完整编程访问与 `get_agent_internals`，可查看本轮实际系统提示词、工具定义和非密钥配置。模式随对话保存，分支继承，新对话默认关闭；点击标题旁「作者模式 · 退出」关闭。引用、转述、附件、网页不作为身份声明，由模型按语义判断；自动/定时任务不暴露开启工具，后端也拒绝其开启请求。全局编程偏好不变，现有核心保护规则、操作系统身份与供应商能力/额度照常生效。


内置技能通过 `read_skill` 按需加载：证据诊断、学习规划、长期记忆、备份/计划批量编辑、工作区脚本批量改动、应用操作与状态解释，以及随包收录的通用技能（shell 脚本、管道与文本处理、正则、写给读者的改动说明）。文件技能的参考文档与 Schema 从仓库的规范文档复制到运行包，不包含私人课表、计划或数据库。用户也可以把自定义技能放到 `~/.agents/skills/` 或助手私有目录 `skills/`，助手会列出并读取；技能名只允许目录名，不能越出技能根。

部分通用技能改编自 MIT《The Missing Semester》课程材料（CC BY-NC-SA 4.0，出处已随技能保留）；此许可与应用自身的 MIT 不同，如需纯 MIT 分发可换成自写版本。

需要用户做决定时，助手调用 `request_user_input` 给出 1–3 个带选项的问题（2–6 个选项、推荐项排第一），界面把它们渲染成按钮，回答作为下一条消息继续本轮对话。问题模型与 deepseek-harness 一致：`multiSelect` 让某一题可多选（勾选后按「提交选择」一次性作答），每题都带自由输入的「其他」（可和多选一起提交），`detail` 放补充说明。

**批准一份提案**也走同一套模型：给问题加 `intent: { kind: "plan-review", approve: "<批准项标签>" }`，界面就不再渲染成普通选项，而是一张「待批准」卡片——顶部提示条、正文（`detail` 里放计划摘要）、底部 **「讨论」** 与 **「批准」** 两个按钮；`approve` 指定的标签是批准项，其余选项是退路。`export_plan`/`export_backup` 产出的文件由助手通过 `review_file` 审阅，向用户展示改动摘要；用户在对话中批准后，助手调用 `apply_file` 应用。

多步工作时用 `update_plan` 维护步骤清单（至多一个进行中），对话页显示进度；一轮结束（完成、出错或被停止）即自动撤下，不留下已经停摆的步骤，模型也可以在轮中传空清单主动撤下作废的计划。系统提示会附带当前编程权限档位（仅工作区 / 完整访问）。

长期记忆有分类、来源、更新时间与确认状态。模型写入均待确认；用户可以改写、确认、删除或补充已确认背景。新对话保留记忆，Pi 会话会保留上下文并自动压缩，下一轮先读最新学情，防止把旧对话当成当前事实。

助手状态目录位于当前数据库旁的 `agent/`：

- `state.json`：配置、人格卡、最近选择的人格（`defaultPersona`，新对话默认沿用）、记忆、各会话的完整界面消息、附件引用、置顶/归档状态、模型返回的思考内容、各会话的 Canvas 文档版本与分支来源、唤醒记录和 Pi 会话路径；新消息不再按 300 条截断。
- `auth.json`：DeepSeek 密钥与 todo 自己发起的 Codex OAuth 凭据；目录权限700，敏感文件600，不出现在状态接口、日志或任务备份。若 Codex CLI 有官方登录，优先读取其 `auth.json`；同账号刷新时同步更新 CLI token。退出 Codex 会清除两处的 ChatGPT token，保留 CLI 认证文件里的其他字段。
- `sessions/`：持久化 Pi 会话；每个对话保留自己的消息与 Pi 会话文件。旧版单会话数据会迁移为一条对话。
- `workspace/`：用户与助手可审阅的修改文件。
- `workspace/attachments/`：上传附件的私有副本与元数据（目录 700，文件 600）；分支引用同一份附件，删除原会话不会破坏分支的附件。
- `tools/`：编程沙箱的工具链与依赖（npm、rustup、pip 等），不进入任务备份。
- `connection.json`：当前运行实例的本机 MCP 地址与随机认证令牌，重启更新。

数据和记忆保存在本机；分析所需内容发送给所选模型服务。完整软件备份不包含认证、助手会话与记忆。迁移助手时应单独处理其私有目录；不要把目录加入 Git 或默认安装包。

## 对话、历史与附件

本轮参照 [ChatGPT 网页端](https://learn.chatgpt.com/docs/web) 的聊天入口和会话导航完善日常交互，保留番茄 Todo 的配色与学习工具。Canvas 是应用本地能力，所有文本模型均可使用；图像生成仅接入官方 Codex 账号。语音不在当前需求范围。联网检索与文件分析继续沿用现有工具，不表示已接入 ChatGPT 网页端的全部服务。

宽屏默认展示历史侧栏，顶栏「会话」可收起或展开；置顶会话在前，其余按今天、昨天、过去 7 天和更早分组。支持按标题、消息正文与附件名搜索、定位匹配消息、重命名、置顶、新建和删除。「归档」只从最近列表收起会话，保留当前阅读、全部消息、附件、置顶与 Pi 上下文；可从「已归档」列表或全文搜索找回并恢复。运行中不能归档或恢复。长对话先展示最近 60 条，可以继续加载早期消息；搜索覆盖完整保存的历史。「导出对话」保存 Markdown 文本及附件名称，附件内容可单独下载；桌面端通过系统保存对话框选择位置。

用户消息可以「编辑」后保存并发送；助手回答可以「重新生成」；两者都创建新对话分支，保留原对话和后续内容。消息的「新分支」只复制到所选消息为止的上下文，不调用模型，随后可自由追问。分支提供返回原对话的入口。编辑和重新生成会再次执行请求中的工具操作，之前已经完成的数据改动不会自动撤销。异常自动唤醒不提供重新生成，用户可用新消息明确安排下一步。

分支使用 Pi 的 `SessionManager.createBranchedSession`，保留工具调用、结果和压缩记录；消息的 `entryId` 对应真实 Pi 节点，不用界面文本重放上下文。旧版消息没有节点编号时，仍可阅读、搜索、复制和导出，但不提供编辑、重新生成与分支入口；可以继续发送新消息，从新消息创建分支。旧版本已截断的历史无法恢复。

空白对话提供学习起步卡片，点击只填入草稿，确认后再发送；未连接模型时直接提供连接入口。输入框随内容伸缩，支持 Enter 发送、Shift + Enter 换行，中文输入法选字不会发送；切换会话保留各自尚未发送的文字与附件。点「附件」、拖入文件或粘贴图片即可添加，发送前可移除。每条消息最多 10 个附件、总计 20 MB，单文件 8 MB；图片支持 PNG/JPEG/WebP，最多 3 张、每张 4 MB。图片直接交给支持视觉输入的模型；文本、CSV、Markdown、代码以及其他文件以本地路径交给现有 `read/bash` 工具分析，复杂格式的解析取决于沙箱工具与模型，未内置 PDF/OCR/Office 转换器。发送失败保留草稿和附件，提交期间继续输入的新草稿也不会被成功回包清空。上传副本随助手目录保留，不进入任务备份；移除待发送附件只解除本次消息的引用。

快捷键：Ctrl / ⌘ + K 搜索历史，Ctrl / ⌘ + Shift + O 新建对话，空输入框按 ↑ 编辑上一条用户消息，编辑时按 Esc 取消。助手消息的「引用」把选中的片段（没有选区时为整条回答）作为引用追加到草稿，不自动发送。

模型通过 Pi 返回的思考内容在「思考过程」中折叠显示，展开状态在轮询期间保留；随消息保存、分支和 Markdown 导出，停止时保留已返回内容。模型没有返回思考内容时不展示，不从答案推测或生成额外过程。

回答支持 Markdown 标题、列表、引用、表格、链接、代码块和数学公式（`$…$`、`$$…$$`、`\(…\)`、`\[…\]`）。消息和代码可以一键复制。原始 HTML 按文本显示，链接仅允许 HTTP(S)/mailto，数学渲染禁用可信 HTML 命令，渲染结果经过清理；字体与渲染库随应用打包，不依赖 CDN。流式回复每次工具调用后展示当前回答，用户停止时保留已有文字并标记「已停止」，供应商错误另行显示并提供重试。

## Canvas 文档工作区

顶栏「Canvas」打开聊天旁的编辑区，助手回答的「打开 Canvas」可将正文转为新文档草稿。用户和助手可编辑 Markdown、纯文本、HTML、CSS、JavaScript、TypeScript、Python、Rust 和 JSON。文档独立于任务数据，不会自动导入为学习计划。

- 「保存」或 Ctrl / ⌘ + S 写入私有 `state.json`，每次有效改动新增一个版本；空正文可保存，单份正文最多 256 KB。草稿切换会话、文档或页面时在当前应用进程内保留，退出应用前需要保存。
- 在正文选中一段，点「解释选段」或「修改选段」，要求会填入聊天草稿，确认发送后才调用模型；先保存文档以便双方读取同一版本。助手使用 `get_canvas` / `save_canvas`，更新必须带最新 `baseRevision`。
- 用户编辑和助手保存使用同一版本校验。过期写入被拒绝，界面保留未保存草稿，可载入最新版本或另存为新文档。运行中用户可继续编辑本地草稿，须等该轮结束再保存。
- 版本菜单可只读查看旧内容，「恢复为新版本」追加一个版本，保留原历史。文档可删除、按所选格式导出。对话分支复制创建分支时的全部 Canvas 文档和版本，随后独立编辑；不会回溯成某条旧消息当时的文档内容。
- Markdown 预览使用现有安全渲染器；HTML 预览在独立来源的沙箱 iframe 内运行内联脚本，禁止联网、提交表单、访问应用与导航父窗口。其余语言预览按文本展示，不直接执行 Python/Rust 等程序。

## Codex ImageGen 与图片

顶栏「生成图片」先填写描述，再由用户发送。助手仅在用户要求生成或修改图片时调用 `generate_image`，经 Pi SDK 的 Codex SSE 请求挂载官方 `image_generation` 工具。没有新增独立调度或重试循环，也不设应用级生成时限；停止沿 Pi 的取消信号传递。图像声明和协议参考 [官方图像工具说明](https://developers.openai.com/api/docs/guides/tools-image-generation)。

当前只支持所选连接为 `openai-codex` 且已登录的场景，使用 Codex 账号额度，不使用网页端免费生图额度。DeepSeek、第三方端点或未登录账号会收到明确错误，不静默切换或扣用另一账号。服务端额度耗尽、登录失效、模型不支持等错误会报告给助手与用户；是否具有 ImageGen 权限仍以实际服务端结果为准。目前没有接入国内生图供应商，也没有自动切换到付费 API 的后备路径。

图片按 PNG/JPEG/WebP 签名校验并保存在私有附件目录，沿用单张 4 MB 的图片上限；本轮生成的图片随助手消息持久化，停止或后续模型出错时，已经保存的图片仍随消息保留。回答里的缩略图可打开大图、下载或「用于图片编辑」。编辑使用附件 ID（最多三张参考图），也可以选择本轮上传的图片。其他模型仍可上传它支持的图片做理解、预览和下载；生成/编辑图片的 ImageGen 调用会被能力检查拒绝。

## 导出、编辑、审阅、应用

批量操作首选文件流程：

1. `export_plan` / `export_backup` 导出最新文件，返回来源数据指纹与 `fileHash`，保留 `.origin` 来源文件。
2. `read_file` 用 JSON Pointer 分段读取，避免将整库灌入上下文。`get_tasks` 也支持分页、项目/目标/完成状态过滤。
3. `patch_file` 带最新 `fileHash` 执行最多200项 add/replace/remove/test；全部编辑成功才写入。失败、路径越界、符号链接及文件哈希冲突均拒绝。
4. `review_file` 使用与实际执行一致的核心预检：校验字段、稳定 ID、历史裁定和保护规则，返回具体差异与导入影响。只预览，不持久化软件修改。
5. 用户勾选已审阅并点击应用。应用时再次核对文件哈希、导出来源与当前数据指纹，并在同一个 Engine 锁内核对后执行，防止审阅至应用期间覆盖新数据。

工作区文件也可由外部编辑器修改，再回软件审阅。界面「导出文件」可复制候选 JSON；外部编辑后把文件放回工作区，保留同名 `.origin`。变更过多时界面只展示前100项，需完整查看导出的文件。

软件数据变化后拒绝旧来源文件，需重新导出并重放修改意图。计划 v4 按稳定 ID 更新配置，保留学习进度和裁定；完整备份 v3 恢复会暂停计时、清除当前锁机并停用导入的定时锁机规则。计时/锁机尚未结束时不能应用工作文件。文件上限20MB，单次工具读取结果上限256KB。

## 外部 MCP

展开「MCP 与私有工作区」，复制当前实例的 JSON 配置到 MCP 客户端。命令形式为：

```json
{
  "mcpServers": {
    "tomato": {
      "command": "/path/to/tomato-todo",
      "args": ["--mcp", "--connection", "/path/to/agent/connection.json"]
    }
  }
}
```

MCP 使用标准换行 JSON-RPC stdio，不启动第二份数据库。它连接正在运行的桌面/预览实例，共享同一个 Engine；关闭软件后不可操作。桥接仅监听127.0.0.1，要求私有连接令牌并拒绝浏览器 Origin。

外部客户端除只读、记忆与文件工具外，可以使用 `dispatch` 直接执行单项 Action，或在 `review_file` 后 `apply_file` 显式应用文件。它不能 `emergencyUnlock` 或 `completeFocus`，紧急退出与提前完成番茄由用户在界面操作；原生能力预检、严格保护、不可逆裁定、来源/文件哈希校验仍然执行。浏览器预览的 MCP 同样不能启用桌面保护。

桥接自己不做超时，`initialize` 按客户端提议的协议版本应答：请求的成败由软件自己的工具逻辑决定，不额外加一层时间上限。

## 接入 MCP 服务器（助手作为客户端）

方向相反的另一半：助手可以调用你自己配置的 MCP 服务器。配置放在软件自己的 `mcp.json`（与 `state.json` 同目录），用的是各家客户端通用、Codex 同款的 `mcpServers` 形状，现成配置可以直接抄过来（完整的自建指南——最小实现、全部字段、exposure、传输选型与排错——见 [MCP.md](MCP.md)）：

```json
{
  "mcpServers": {
    "seat": {
      "command": "/path/to/node",
      "args": ["/path/to/seat-mcp/server.mjs"],
      "env": { "SEAT_SESSION": "/path/to/state.json" },
      "exposure": "codemode",
      "description": "图书馆座位：查空座、看订单、出方案"
    }
  }
}
```

座位这个例子的完整实现与逆向记录见 [LIBSEAT_MCP.md](LIBSEAT_MCP.md)（华南农业大学图书馆座位预约：接口还原、验证码与会话的绑定规则、读图命中率实测 3/10 与重试数学、自定义求解器的接入契约）。

- 传输由随包运行时自带的 MCP 客户端处理：`command`（stdio）或 `url`（streamable HTTP，支持 `${ENV}` 头与 OAuth 登录）；`enabled: false` 单独停用。配置坏了不会静默：`list_mcp_servers` 会连校验错误一起报出来，服务器自己的 `notifications/message` 追加到同目录的 `mcp.log`。
- 工具名为 `mcp__<server>__<tool>`，资源用 Codex 同款的 `list_mcp_resources` / `list_mcp_resource_templates` / `read_mcp_resource` 读取。
- **暴露方式**：`codemode`（默认）只在代码里调用，`deferred` 由 `tool_search` 按需加载，`direct` 需要把工具名显式写进工具清单。应用用的是策展过的工具清单，所以默认走 `codemode`/`deferred`：既不撑大工具的声明，也保证只读轮次不会凭空多出一堆外部能力；配成 `direct` 的服务器在这里不会被声明。
- **只在用户主动发起的对话里连接**：异常自动唤醒不加载任何 MCP 服务器（座位、下单这类服务器不该在无人确认时被唤醒），也没有 `add_mcp_server` / `remove_mcp_server`。这两个工具等价于 `codex mcp add` / `remove`，写的就是上面的 `mcp.json`。
- **服务器不在编程沙箱里**：它是你配置的那个程序，以你的身份、在沙箱之外运行；`add_mcp_server` 因此只在用户明确要求时使用。
- 每次请求都会新建会话，MCP 服务器随之连接；会话结束（含应用退出）时一起关闭，不残留后台进程。

## 助手的「手」

让助手在界面上「做给人看」：一句话脚本演成一段动画，人手、键盘、讲稿一起动。形状照两件现成实现来——matinee（可编程幽灵光标：`moveTo/click/type/say`，覆盖层 `pointer-events: none`、`aria-hidden`、尊重 `prefers-reduced-motion`）与 demowright（可见光标 + 按键 HUD + 字幕 + 音效）。实现是 `src/hand.ts`（无 React，一层挂在 `body` 上的覆盖层）。

整段脚本结束或出错时自动收起手势、讲稿与键盘，无需末尾显式 `hide`；失败仍报告给调用方，后续排队演示继续执行。

脚本是一串步骤，`:kind` 取 `move / click / type / highlight / say / keyboard / wait / hide`：

- 位移动画沿一条带轻微过冲的贝塞尔路径走，落点前收一下，看起来像手而不是补间；目标不在视野里会先滚进来。
- `click` 会在落点画涟漪、把手按下去，`real: true`（默认）时**真的**把 `click` 派发给目标元素，所以演示里的按钮真的会被按到。
- `type` 会浮出一块小键盘，逐键高亮（中文走「输入」键帽），并逐字符写进真实输入框——因为应用每次输入都会重绘，手每敲一个字符**重新取一次目标元素**，否则后面的字会写进已经脱离文档的旧节点。
- `say` 是手边浮出的讲稿，一行一行读出来（字数多则读得慢），`hold: true` 让最后一行留到脚本结束，后面的动作在它旁边发生。文字内容完全由脚本给，也就是由模型给。
- 音效只有四种（移动的气声、点击的轻扣、按键的脆响、翻行的轻铃），自己拿一个 `AudioContext`，不去打断应用那套关键节点音效；开关与音量跟随「关键节点音效」设置。

驱动方式：助手用 `show_me` 工具（`{label, steps}`）把脚本交上来，Rust 存成 `live.hand`（带自增 `serial` 与生成时间），界面按 `serial` 演一次——只演新鲜的（2 分钟内生成），用户过一会儿才回到这一页时不会突然动起来。脚本在这里校验：1–12 步、讲稿 1–4 行每行 ≤300 字、一次输入 ≤200 字、单次等待 ≤8 秒。`show_me` 与其它会动界面的工具一样只在用户主动发起时可用，自动唤醒不出手。另外 `window.tomatoHand.run/step/hide` 留给调试与测试，`?hand=demo` 演一段课表阻塞时段的示范（`src/hand-demo.ts` 的 `blocksTour`）。

**什么时候值得演**由技能说，不由流程钉死：`tomato-guide` 里写了判断（不熟的用户/容易点错的步骤才演；熟手直接走 MCP 或导出导入，一句话能说清就用文字）与「工具就是工具、按当下最省的那条路走」。工具本身始终可用，没有按用户等级硬编码的开关。

**演自己做过的事**：助手每改一处数据（建/改任务、记课表、勾任务，以及 `dispatch` 的常见 Action）都会留一条「事迹」——一句人话，加上能定位就带的选择器（`[data-task-id=…]`、`[data-block-id=…]`、`.blocks-card`）。一轮结束时（收到 `done`）打包成一批 `deeds`（自增 serial，一轮最多 6 条），界面演一遍：先点回改动所在的页面，把手停在那一行上标出来，再逐条说出改了什么。用户不在助手页、或这批超过 2 分钟就不再补演。所以「AI 改了什么」不靠模型复述第二遍，系统提示据此让它只讲**为什么**。

## 定时任务（到点让助手自己办事）

异常唤醒只会分析；**定时任务**是用户排定「到点去做」，助手自己也能排。模型放在助手状态里（`state.json` 的 `schedules`），一条 `{id, name, at, repeat, instruction, remindMinutes, enabled, firedAt}`：`at` 是 once 的 `YYYY-MM-DDTHH:MM`，daily/weekdays 只写 `HH:MM`；最多 20 条。

触发在 `observe` 里（每次快照轮询都会看）：到点、助手已启用且已连接、空闲、没有正在计时或锁机就出发。**它不受异常唤醒那一套限制**——不看「自动唤醒」开关、不看每日上限与冷却、也不看安静时段，因为这是用户明确排的安排；但这一轮带的是**完整工具集**（含 MCP 与改数据），所以指令要自己写清目标与边界。一次性的用 `firedAt` 防重、周期性的按天去重，晚到 30 分钟以上就不再补做（避免半夜突然动手）。

工具：`save_schedule`（不传 id 新建，传 id 更新并保留已触发记录）、`delete_schedule`、`list_schedules`（只读，唤醒轮次也能看）。状态接口返回 `schedules`。怎么排才靠谱（挑有网时段、预约后必须建按时签到的任务、提前提醒、必要时提前锁机）写在 `tomato-guide` 技能里，平台不规定流程。

界面：顶栏「定时」浮层列出所有定时任务（时间、周期、提前提醒/锁机、是否已触发），可启用/停用、删除，也能手动新建。字段里 `lockBeforeMinutes` 由平台执行：到点前那段时间起一个 **strict** 快速锁机（锁到点），只在该条安排显式设了分钟数、且当前没有锁机时才做，并且当天锁过一次不再重复。

助手也能写自己的技能：`save_skill {name, description, body}` 写进 `agentDir/skills/<name>/SKILL.md`（带 front-matter），`delete_skill` 删除；`available_skills` 会把这份目录和随包技能一起列出，所以下一轮 `get_context` 就能看到。名字只允许小写字母、数字与连字符，正文 ≤20000 字，且只动这个私有目录（内置技能与用户手写技能删不到）。

## 验证

`cargo test -p tomato-core -p tomato-agent` 覆盖诊断、权限、记忆确认、补丁原子性、差异审阅、来源冲突、空闲排队和重启冷却，以及完整历史搜索、分支附件引用与停止状态持久化。`node --test tests/agent.mjs tests/agent-workspace.mjs` 通过本机模拟模型验证真实 Pi SDK 的流式工具调用、恢复和分支，并通过真实 Rust、MCP stdio、Chromium 验证附件读取、编辑/重试上下文、原会话保留、复制、渲染、停止与文件应用；同时覆盖 Canvas 的真实工具写入、版本冲突/恢复、分支隔离、HTML 沙箱与小屏预览，以及真实 Pi Codex SSE 图像结果、参考图、非 Codex 拒绝、额度错误和取消。不调用付费模型，不启用用户桌面保护。模型流程使用临时可执行文件，避免 `target/debug/agent` 中的安装运行包遮住本次构建。

真实账号与桌面保存行为由用户自测：启动桌面版并连接模型，在助手页上传文本资料并发送；用消息的编辑、重新生成和新分支入口核对上下文，通过「返回原对话」确认原文保留；归档后在搜索和已归档列表找回、恢复，检查思考内容的折叠、停止保留和重启恢复；换视觉模型发送图片，检查停止标记与重试；下载附件或导出对话时选择系统对话框的保存位置，也试一次取消。PDF/Office 等格式按沙箱工具实际可读性验收。

新增功能的真实账号自测：选择官方 Codex 连接并登录，点「生成图片」描述一张学习卡片，检查图片预览和下载；用「用于图片编辑」提交修改要求，检查参考图被沿用。试一次停止；再切换 DeepSeek 点生图入口，确认清晰报错且没有图像请求。Canvas 可在 DeepSeek 下让助手创建笔记、选段修改，并在另一轮编辑期间保留本地草稿，核对版本冲突与恢复。

Rust 开发、测试与发布均关闭增量编译；未变更的依赖仍由 Cargo 按内容检查复用。Agent 运行包每次清理重建，避免退役文件残留。

对话阅读：流式回答在接近底部时自动跟随；向上阅读后保持位置，可点「回到最新消息」继续跟随。选中消息文字期间暂停消息区域刷新，取消选择后继续更新；切换会话默认展示最新消息。
