# 学习计划文件 v4

入口：**偏好设置 → 学习计划 → 导入计划 / 导出计划**。UTF-8 JSON，上限 20 MiB；机器定义见 [plan.schema.json](plan.schema.json)，通用示例见 [plan.example.json](plan.example.json)。计划交换模板、印刷规则、印刷记录、未完成实例及容器，不交换完成进度、专注历史、计时器或本机设置。

## 模板 → 印刷 → 实例

顶层字段：`format: "tomato-todo-plan"`、`version: 4`、`pomodoroMinutes`（1–180）、`projects`、`tasks`，以及 `templates`、`prints`、`goals`、`habits`（省略数组时为空）。

- **模板**：`{ id, shape, printing, automatic, printAheadDays }`。`shape` 保存标题、备注、项目/目标/习惯组引用、单次时长、预计番茄数、标签、默认优先级、普通组重修窗口和子任务文本。没有完成、日期或统计；没有手填的任务类型。
- **印刷规则**：简单单次 `{ kind: "once", date: null, time: null }`；非重复日程表 `{ kind: "calendar", slots: [{ time: "09:00", dates: ["2026-10-12", "2026-10-14"] }, { time: "15:00", dates: ["2026-10-12"] }] }`；重复周期 `{ kind: "weekly", slots: [{ time: "09:00", days: [1,2,3,4,5] }, { time: "15:00", days: [2,4] }] }`。一份形状在多个开始时间复用；每个开始时间对应多个日程日期或周期单元。日程表最多 49 个时段、总计 366 项；同一开始时间的日期合并到一个时段，不重复。默认周期是一周（周一至周日）。星期 1–7；同一天可安排多个不同时间，最多 49 个时段，同一星期和时刻不能重复。全部时段不填时间时属于普通组；定时与不定时不能混在同一模板。
- **印刷记录**：`prints: [{ templateId, date }]`，独立于实例，记录该模板该日期的整批印刷。删除实例、编辑模板、恢复备份、重复导入都不会把这天重新补满。无日期实例使用 `date: null`。它是防重的安排记录，不是完成进度。
- **实例**：`tasks` 保存一次执行的形状快照、`templateId`、具体 `dueDate`、`reminderTime`、生成时的 `recurring` 属性。实例不保存重复规则；完成实例只改变本实例。子任务只有 `id/title`，导入从未完成开始。

界面创建时按临时任务 / 手动模板 / 自动模板渐进显示信息。临时任务可一次印出一条或整份非重复日程，不保存模板；手动模板隐藏预印配置。重复/非重复与手动/自动是独立选项。预计用时按分钟输入，由界面向上换算核心 `estimate`，预览实际预留专注和休息时间，短任务自动使用更短的 `focusMinutes`。交换文件继续用 `estimate` 表示内部计划段数。

`automatic` 默认 false，模板会保留供手动复用。单次模板可以手动用于不同日期，同一日期只印一次。自动单次规则需填写 `date`；自动每周规则不设终点。

`printAheadDays` 默认 7，范围 0–90。每次启动或引擎轮询都重新检查尚未印刷的安排，不依赖某日期是否“首次进入范围”。非重复规则印出截止今天 + 预印天数的日程（包括仍可执行的逾期日程）；重复规则印完当前周至预印日期所在周的**完整周期**，可超过预印窗口直到周期末。0 表示本周完整周期或截至今天的非重复日程。关机期间无后台或云服务，恢复运行时补齐尚未报废的遗漏。

手动印刷与自动印刷均支持重复和非重复。重复模板选择的任意日期代表其所在周期，印出该周期内全部单元（日期跨多周时逐周印完）；非重复日程选择范围后批量印出其中全部开始时间及日期，保存时一起印刷则印完整份日程。单次模板还可复用于其他日期。已印日期自动跳过；手动操作不持续扩展。关闭自动印刷不修改已经生成的实例。

## 管辖和报废

| 管辖   | 条件                                | 逾期后                                     | 报废判断                                |
| ------ | ----------------------------------- | ------------------------------------------ | --------------------------------------- |
| 普通组 | 不属于目标；定时和重复不同时出现    | 重修窗口内进入「待补」队列                 | 计划块结束 + `scrapMinutes`；跨午夜作废 |
| 目标组 | `goalId` 非空，可重复，提醒时刻可选 | 配对节点未裁定时可待补；未配对没有默认截止 | 配对节点被信号裁定成功或失败            |
| 习惯组 | 定时且重复，或由习惯组生成          | 不重修，已印实例漏做记缺勤                 | 计划块结束即作废                        |

计划块 = 预计番茄数 × 单次时长 + 番茄之间的短/长休息。`scrapMinutes` 是分钟数（0–10080），普通组默认 0，边界时刻即报废；当天内有效。目标/习惯的实例不使用此静态窗口。

**印刷前过滤静态报废**：普通和习惯的手动/自动印刷跳过已过静态时间窗口的候选实例；目标印刷不由主线控制，生成后按 ID 与执行时间配对，若节点已裁定，实例立即报废。仅逾期、仍允许补做的实例照常印出并进入「待补」队列。习惯没有重修窗口，因此不会补印已过计划块的时段；同一天尚未报废的其他时段仍可印刷。一旦这天产生了实例，整天批次记为已印。

目标组采用 `{ id, name, nodes: NodeSpec[] }`，没有统一产出单位、计量方式或组截止日期。目标与习惯组互斥，但目标允许周期模板。项目是独立的学习环境维度，`appWhitelist` 提供时替代通用白名单，省略时不覆盖本机项目配置。愿景是纯标记，不参与印刷。

## 主线节点配置

`goals` 的每一项为 `{ id, name, nodes }`，节点配置结构如下（通用示例，无默认自动导入）：

```json
{
  "id": "example-mainline-node-1",
  "name": "学习阶段",
  "start": "2026-10-12T00:00",
  "end": "2026-10-19T00:00",
  "requiredTasks": 1,
  "confirmationRequired": false,
  "signal": null,
  "blockSuccess": "never",
  "blockFailure": "never"
}
```

`start/end` 是本机当地时间，区间 `[start,end)`，一条主线最多 200 个不重叠、按时间排列的节点；名称 1–80 字，`requiredTasks` 1–50000，默认 1。配对要求有实际实例，所有配对实例均完成，并达到数量要求；若 `confirmationRequired` 为 true，还需要通过 `confirmNode` 保存人工确认。无提醒时刻的有日期实例按 00:00 配对，无日期实例不配对。

`signal` 可为 null，或 `{ kind, direction, at, condition }`：`kind` 为 `success/failure/check`；`direction` 为 `head/tail`；`at` 为同格式本地时间；`condition` 为 `always/completed/incomplete`，默认 always。check 仅末节点可使用，方向必须 head、条件必须 always。成功/失败到时后持续等待条件满足，发出一次；检查到时发出，之后在新的未裁定节点完成时再次检查。重启不重放已经发出的普通信号。

`blockSuccess/blockFailure` 分别指定接收成功/失败信号时的规则：`never/always/unpaired/unfinishedTasks/incomplete/completed`。普通无信号节点只能设 never。判断针对接收节点自身；自身信号和末节点检查不能被阻断。

计划只交换配置，不交换 `confirmed/emitted/result`、实例 `nodeId`、配对记录、信号记录或 ID 历史。导入现有 ID 时保留本机配置和进度；新任务在导入后配对。新的主线规则已经到时可能立即发信号。完整恢复必须使用备份 v3。

独立实体 ID 在所有实体类型间唯一，最多 200 个 UTF-8 字节；本机删除历史中的 ID 不能通过计划导入复用。子步骤的局部编号用于模板与实例形状同步，不是独立实体或主线配对标识符。

## 修改、删除与合并

编辑模板默认只影响以后印出的实例。「同步到未完成实例」是显式操作：同步尚未裁定且未完成实例的标题、备注、项目、时长、优先级、标签、普通组重修窗口及子任务文本，保留日期、管辖、完成步骤、完成实例和专注历史。

删除模板保留已印实例，只清 `templateId` 并停止后续自动印刷。删除尚未发信号且无裁定历史的目标组、项目或习惯组会把所属实例移出，保留任务；同时清理未来模板引用，删除习惯组会停止其模板。愿景继续随所属项目/目标连带删除。

导入先完整校验候选数据，再原子提交。相同 ID 的模板、目标、习惯组、任务和任务进度保留；印刷记录取并集。项目 `appWhitelist` 提供时覆盖本机值，省略时保留。新增任务和模板若没有指定 `focusMinutes`，预计番茄数按 `ceil(estimate × pomodoroMinutes ÷ 当前专注分钟数)` 换算，超过 99 拒绝导入；指定单次时长时不换算。整个操作不修改设置、计时器或专注历史。

导出包括全部模板、印刷记录、目标/习惯组、未完成实例及引用的项目。保留步骤 ID 与文本，不导出步骤完成状态。完整恢复使用 [备份 v3](BACKUP_FORMAT.md)。

## v1/v2 计划导入

继续接受旧计划；v1 不接受非空 `reminderTime/focusMinutes`，v2 支持这些字段。旧计划只能包含原有任务/项目字段，不接受非空 v3 容器、模板、印刷记录或引用。

旧非重复任务转换为手动单次模板和一个实例；旧每日/工作日/每周任务转换为自动每周模板（预印 0 天）及实例。模板 ID 为 `plan:<原任务 ID>`，原任务 ID 和已有本机进度保持不变。生成后的实例不拥有重复规则。旧文件的 `repeat` 仅用于边界转换；v3/v4 实例只接受缺省或 `none`。v3 计划只在不含旧目标组时支持；主线节点必须使用 v4。

Schema 检查结构；Rust 还检查有效日期、引用、ID 唯一性、星期/时刻重复、UTF-8 长度、管辖约束和合并后总量。未知计划字段和版本拒绝导入。

预览服务：`GET /api/plan` 导出，`POST /api/action` 接受 `importPlan`、`saveTemplate`（可含 `printDates`，保存和印刷原子执行）、`printTemplate`（`id/dates`）、`syncTemplate`、`deleteTemplate`、`printInstances`（`shape/printing`，一次印完非重复日程，不保留模板）、`saveHabitGroup`（`id/name`，多个不同形状可共享分组）、`saveGoal`（`id/name/nodes`，配置稳定主线）、`confirmNode`（`goalId/nodeId/confirmed`，保存未裁定节点的人工确认）。桌面使用同一核心 Action；文件对话框仍走 `export_data/read_import` 的 `plan: true`。通用示例不会自动装入默认数据。
