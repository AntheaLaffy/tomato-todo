# 学习计划文件 v1

学习计划用于编排、编辑和交换任务；完整备份用于恢复进度与本机设置。分开这两种文件，能让导入一份新计划时保留当前任务、专注记录与计时状态。

定时锁机和严格模式属于本机执行策略，不写入计划文件。需要导出这些配置时使用 [完整备份标准](BACKUP_FORMAT.md)。计划格式仍为 v1；任务备注可写建议睡眠时段，但不会因此启用锁机。

在 **偏好设置 → 学习计划** 中使用「导入计划」「导出计划」。文件采用 UTF-8 JSON，建议命名为 `名称.tomato-plan.json`，不超过 20 MiB。字段名区分大小写，不接受未定义字段。机器可读定义见 [plan.schema.json](plan.schema.json)，可直接修改的示例见 [plan.example.json](plan.example.json)。这是本项目的格式，不宣称兼容其他同名应用。

## 文件结构

```json
{
  "format": "tomato-todo-plan",
  "version": 1,
  "pomodoroMinutes": 25,
  "projects": [
    { "id": "practice", "name": "自主学习", "color": "#849b7d" }
  ],
  "tasks": [
    {
      "id": "practice-chapter-1",
      "title": "完成一章练习并复盘",
      "projectId": "practice",
      "estimate": 2,
      "subtasks": [
        { "id": "attempt", "title": "先独立完成练习" },
        { "id": "review", "title": "记录错因并复述方法" }
      ]
    }
  ]
}
```

顶层五个字段全部必填。`format` 固定为 `tomato-todo-plan`，`version` 固定为 `1`；`pomodoroMinutes` 为整数 1—180，表示文件中一个预计番茄对应的**专注分钟数**，不包含休息。`projects` 最多 500 项，`tasks` 最多 50,000 项，可为空数组。

项目的 `id`、`name`、`color` 必填。ID 为非空字符串，建议使用 UUID 或带计划前缀的稳定 ID；名称为 1—40 个字符且不能全为空白；颜色是 `#RRGGBB`。同名不同 ID 是不同项目，导入不会根据名称猜测合并。

## 任务字段

| 字段 | 类型与范围 | 省略时 |
| --- | --- | --- |
| `id` | 非空字符串，文件内任务 ID 唯一 | 必填 |
| `title` | 1—200 个字符，不能全为空白 | 必填 |
| `notes` | 字符串，UTF-8 不超过 50,000 字节 | 空字符串 |
| `projectId` | 文件内某个项目的 ID，或 `null` | `null`，收件箱 |
| `dueDate` | 有效的 `YYYY-MM-DD` 日期，或 `null` | `null`，未安排 |
| `priority` | 整数 0—3：无、低、中、高 | `0` |
| `estimate` | 整数 1—99，按文件的 `pomodoroMinutes` 计数 | `1` |
| `tags` | 字符串数组，最多 20 个，每个最多 40 字符 | `[]` |
| `subtasks` | 最多 200 项；每项含必填 `id` 和 `title` | `[]` |
| `repeat` | `none`、`daily`、`weekdays`、`weekly` | `none` |

子任务 ID 在所属任务中唯一且非空，标题要求同任务标题。ID 区分大小写；同一份计划再次导入时，**保留原 ID**。修改标题或日期不应顺手重新生成所有 ID。

`dueDate` 是应用本地日历中的计划日期，没有时区、开始时间或课程提醒含义。建议时段、地点、验收要求写在 `notes` / `subtasks` 中。`repeat` 在完成任务时按应用规则生成下一次任务；有限试行计划应使用明确日期和 `none`，避免试行结束后继续生成。

## 导入与导出行为

- **合并新增**：文件内项目与任务先完整校验，已有相同 ID 的项目、任务全部保留；其名称、备注、日期、步骤进度也不会被文件覆盖。新增内容一次性保存；任一错误使整次导入失败，不留下半份计划。未出现在文件里的本地任务不会删除。
- **不用于更新既有任务**：再次导入修改过但 ID 相同的任务仍会跳过。修改现有任务请在应用内编辑；确实要新建一个不同任务时才换 ID。同 ID 任务即使已经完成也不会复活。删除过的任务再导入会重新创建，因为应用不保存删除墓碑。
- **保留本机状态**：不导入或更改设置、白名单、专注历史、计时器。正在受专注保护时，导入仍受现有禁止修改规则约束。正常计时到期会按引擎规则结算。
- **换算用时**：新增任务的预计番茄数为 `ceil(estimate × pomodoroMinutes ÷ 当前专注分钟数)`。例如文件中 2 个 25 分钟番茄，导入当前 30 分钟设置后仍为 2 个。向上取整会略微放宽时间预算；超过 99 个时拒绝导入，需先拆分任务。
- **计划不含执行进度**：新增任务与子任务从未完成开始，创建时间取导入时刻；不接受 `completed`、`done`、`sessions`、`settings` 等额外字段。
- **导出范围**：全部未完成任务及其引用的项目，保留任务/步骤 ID、备注、日期、预计番茄数、标签和重复规则；包含全部步骤文本，但不包含步骤完成标记。已完成任务、未引用的项目和历史记录不导出。需要完整迁移时使用「导出备份」。

Schema 检查字段和单项范围；Rust 核心还会检查有效日期、ID 唯一性、项目引用、UTF-8 字节长度、空白标题，以及合并后的总数量和换算范围。所有客户端共用核心校验。

## 完整备份与版本演进

原有 `tomato-todo-backup.json` 继续使用 `AppData` 的 `version: 1`：`tasks`、`projects`、`settings`、`timer`、`sessions`、`lock`，没有 `format: tomato-todo-plan` 标记。旧文件缺少 `lock` 或 `settings.protection.strict` 时使用关闭默认值。使用「导入备份」会确认后替换整份数据、暂停计时器、停用导入的定时规则并清除当前锁机。不要把计划文件直接交给备份入口，或把备份改个后缀当作计划。

v1 的未定义字段和未知版本均拒绝导入，避免拼写错误或未来字段被悄悄忽略。新增影响语义的字段时必须升级版本，先实现明确迁移后再接受；不通过放宽校验改变既有 v1 的含义。

预览服务：`GET /api/plan` 导出，`POST /api/action` 接受 `{ "type": "importPlan", "plan": <上述文件> }`。桌面通过同一个核心 Action 合并；文件对话框使用 `export_data` / `read_import` 的 `plan: true` 参数。私人学习资料只存放在本地 `artifacts/planning/`，文档示例不会自动载入任务或默认种子。
