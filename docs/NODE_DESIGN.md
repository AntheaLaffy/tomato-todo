# 主线与节点设计理念

状态：已实现，包含核心、编辑器及行为验证。日期：2026-10-10。

本文保存已确认的设计理念与当前实现边界。配置交换使用计划 v4，完整运行状态使用备份 v3；具体字段见对应格式文档。

## 目标组承载主线

一个目标组可以包含听课、练习、实验、复盘等不同任务，因此组本身不设置统一产出单位。主线表达阶段目标及其时间信息；具体任务表达为达成目标而采取的行动。

每个任务组拥有永久、唯一的配对标识符。任务组改名、主线编辑、节点时间调整都不能改变这个标识符。标识符不能根据名字、主线内容或日期重新计算；不同任务组即使同名，也不能共用标识符。实现时可以直接复用任务组的稳定 ID。

主线可以在没有任何任务实例时独立存在。不同主线拥有各自的节点时间和阶段区间，不要求共用一套周边界。

## 模板印刷，实例配对

实例由模板印刷。主线和任务组不印刷实例，也不负责决定模板是否、何时或如何印刷。

实例与节点配对需要同时满足两方面：

1. 实例的配对标识符与任务组对应。
2. 实例的执行时间与节点承载的时间范围匹配。

匹配依据是执行时间，不是实例印刷时间。同一天的其他任务组实例不能仅因时间相同而进入该节点。

节点关心三个过程事实：是否成功配对任务、配对任务是否全部完成、节点是否完成。即使节点要求完成某个数量的任务，没有实例进入时也没有实际配对，不能把空集合的“全部完成”当成节点已完成。

执行资格、节点裁定和实例报废通过配对关系产生作用；不能将这些作用改写成主线取消或启动模板印刷。

## 完成与成功、失败分开

节点的完成情况是过程信息，成功和失败是最终裁定。

节点承载时间信息，但没有独立的“过期”状态。经过一个时间点、尚未完成或主线尚未结束，都不直接使节点失败，也不自动使配对实例报废。时间可以触发信号，裁定由有权发信号的节点完成。

节点最终结果为尚未裁定、成功或失败。成功和失败一旦产生就永久固定，后续信号、完成情况变化或普通编辑均不能改写。节点已完成本身不等于已经成功；未完成节点也可能被成功信号直接裁定成功。

节点一旦成功或失败，其管辖的全部实例都报废，包括已经完成的实例。报废结束实例的可执行生命周期，不删除实例、完成记录和专注历史，也不把未执行的任务伪装成已完成。

## 发信号的权限与条件

普通节点默认没有发出报废信号的权限。重要节点可以获得该权限；末节点拥有专属的检查语义。

报废信号的发出条件支持：

- 单独由时间条件决定。
- 由时间条件与发出节点自身的完成情况共同决定。

具体时间和完成条件属于信号触发规则，不是节点的过期规则。

## 传播方向与裁定内容独立

前向与后向描述信号在主线中的传播方向，不固定对应成功或失败。为避免歧义，界面和实现可以直接使用“向头节点”和“向尾节点”表达方向。

| 信号内容 | 对尚未裁定的接收节点的作用                   | 限制                                     |
| -------- | -------------------------------------------- | ---------------------------------------- |
| 成功     | 直接裁定成功，不要求节点已完成               | 可向头或向尾传播，接受阻断规则           |
| 失败     | 直接裁定失败，不要求节点未完成               | 可向头或向尾传播，接受阻断规则           |
| 检查     | 已完成的节点裁定成功；未完成节点保持尚未裁定 | 仅末节点可以发出，固定向头传播，不可阻断 |

成功、失败信号都属于报废信号：它们裁定节点，并结束该节点管辖实例的生命周期。“成功”与“失败”不能因最终都报废任务而合并，否则无法解释免做、认可、失格或验收否定等不同结果。

任何信号均不得覆盖节点已有的成功或失败标志。检查信号不能把已经失败的节点改成成功，也不自动把未完成节点判为失败。

## 接收与局域阻断

发信号的节点必定接受自己的信号，自身阻断设置不能拒绝自身信号；不可逆裁定规则仍然适用。

报废信号沿主线传播。普通节点接受信号；遇到另一个有权发信号的节点时，该节点可以拒绝接收，从而阻断后续传播。因此，信号具有局域性，实际边界由沿途有发信号权限节点的接收设置决定，并非遇到这种节点就必然停止。

拒绝发生在接受和裁定之前：被拒绝的外来信号不裁定该边界节点，也不能越过它继续传播。

每个有发信号权限的节点，可分别为外来的成功信号、失败信号配置：

| 接收设置   | 行为                                     |
| ---------- | ---------------------------------------- |
| 不阻断     | 默认，接受并继续传播                     |
| 无条件阻断 | 拒绝该类外来报废信号，停止传播           |
| 条件阻断   | 条件成立时拒绝并停止，否则接受并继续传播 |

条件检查接收节点自身，按信号到达时的情况判断。首版提供单选条件，不要求用户编写表达式：

| 条件                 | 判断                                 |
| -------------------- | ------------------------------------ |
| 尚未配对任务         | 没有成功配对的实例                   |
| 配对任务仍未全部完成 | 已有配对实例，其中至少一个未完成     |
| 节点尚未完成         | 节点完成状态为否，包括尚未配对的情况 |
| 节点已经完成         | 节点完成状态为是                     |

例如一个节点可以放行成功信号、阻断失败信号，也可以反过来；每种信号分别设置接收规则。

末节点的检查信号不能被拒绝或阻断，向头节点执行检查。已有最终裁定仍然不可修改。最终裁定不可修改与是否阻断传播是两个独立约束。

## 使用场景与取舍

### 建议内容结束后免做

导学内容建议完成，但不影响晋级。重要节点到达指定时间后，向头发送成功信号，将其传播范围内尚未裁定的导学节点判为成功，配对实例报废。此后不再要求执行这轮导学任务，其实际完成情况仍如实保留。

### 未获得晋级资格

晋级节点按时间及自身未完成情况发出向尾的失败信号，使受影响的后续节点失败。独立的其他阶段可以通过阻断节点免受该信号影响。资格结果不参与模板印刷逻辑。

### 向尾成功：免修补课

入门测试满足要求后，向尾发送成功信号，将指定的基础补课阶段直接判为成功。项目实践节点可以阻断成功信号，避免免修影响必须执行的项目任务。免修不会把补课任务记录成实际做过。

### 向头失败：验收否定准备成果

听课和练习任务已经完成，但阶段验收未通过。验收节点向头发送失败信号，将相应范围内尚未裁定的准备节点判为失败。独立的前置阶段可以阻断失败信号，已裁定成功或失败的节点不变。失败不会抹掉此前的学习记录。

### 末节点检查

正常结束时，末节点向头发出不可阻断的检查信号，将已完成且尚未裁定的节点变为成功。单独的检查信号不裁定未完成节点失败；不能补出讨论中没有规定的自动失败规则。

## 数据记录原则

为保留分析能力，应分别保存配对事实、任务完成记录、节点完成情况和最终裁定。一次裁定应能追溯发出节点、信号内容、传播方向、触发与接收时间，以及阻断位置和原因。

这样可以区分实际执行完成、信号认可或免做、验收否定和失去资格。分析既能观察节点结果，也能解释配对实例为何结束生命周期。

## 当前实现决策

- 配对采用执行开始时间与不重叠的 `[start,end)` 区间；有日期无时刻按当地 00:00，没有日期暂不配对。
- 完成要求默认为至少一条实际配对任务且全部完成；支持增加最少数量以及人工确认。确认本身不产生成功裁定。
- 已有配对持久保存。编辑主线范围只影响之后建立的配对；修改未裁定任务的组或执行时间是显式重新配对。删除任务保留配对完成事实。
- 普通信号到时后持续等待自身完成条件，发出一次，阻断后不自动重投。末检查在新的未裁定节点完成时继续检查，不把未完成节点自动判失败。
- 同时可发的信号按触发时刻、任务组 ID、来源节点 ID 顺序执行。信号和裁定记录随数据库、备份保存，重启不重放普通信号。
- 已配对、已发信号或已裁定节点不能删除。已裁定节点只允许改名，规则、范围和结果冻结；已发出的信号不能改写。新的轮次使用新任务组和节点。
- 后来配对到已裁定节点的实例同样报废。正在专注的实例被节点裁定后停止计时，保留实际已用时间，不虚构任务完成或番茄完成。
- 所有独立实体 ID 全局唯一，删除后永久保留。备份保留并合并历史登记；计划不能复用本机历史 ID。撤销删除只能恢复登记中的原任务，同一实体保留原 ID。
- 完整备份不能倒退本机已有裁定；计划导入同 ID 时保留本机配置和进度，不导入运行裁定。

未来扩展跨区间配对、信号重投或新一轮操作时，仍须保持成功/失败不可改写及历史 ID 不复用。
