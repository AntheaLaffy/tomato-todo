# 围绕实际学情规划学习

先读取 `tomato-todo`，用 `tomato_get_context`、`tomato_get_tasks` 和 `tomato_get_study_progress` 核对当前状态。为本机用户规划个人学习任务前，读取 `~/study/考研时间规划/我的情况-给智能体.md` 与同目录的 `课表补充-时间说明.md`；后续说明与实际数据有冲突时指出并核实，不静默沿用旧约束。路径失效时继续处理独立部分，只询问影响排期的缺项。

## 固定真实容量

核对愿景是否仍有意义、期限、当前学习位置、任务难度、固定课程、吃饭午睡和收工时间。历史专注时长和每日番茄目标都不是全天可用容量；课程已到点、任务已勾选不等于掌握。估时与实测分开，新增估时注明依据或待验证。

应用 `blocks` / `todayBlocks` 是课表占用：`attention=required` 整段避开，`light` 时段可并行作业或听其他课。没有数据先核实哪些课能并行，再按用户要求补齐课表；不默认所有课程都可占用或都不可占用。跨午夜时段与星期按当前格式处理。

座位、开放时间与课程资源等外部事实使用实际可用的 MCP 或原始来源查证，并说明来源；不能仅凭旧记录承诺有座位或课程可用。未接入的服务不假装已经查询。

## 排期与调整

1. 先放固定约束和休息，再按依赖与期限安排关键下一步；保留应对估时偏差的缓冲，比例依据用户实际反馈，不硬套统一日程。
2. 成果可观察，如“完成一组题并解释错因”；长任务拆成可开始的段落。已完成、已作废的不重新安排，未完成的不自动累加到次日。
3. 检索练习用于测掌握，间隔复习用于保持，错题复盘用于找原因；知识困难优先解决，不能用增加任务掩盖困难。
4. 跨科合计课程、作业、复习与测验负荷。正式课程和测评同时使用 `exam-teaching`；课程量不再叠加为作业配额，重负荷时直接减量。
5. 检查本机日期、时区、番茄段数、每段时长、段间休息、提醒和截止时间。任务 dueDate 必填，提醒时间可空；用户未要求精确时刻时不凭空添加提醒。
6. 说明变更理由、关键假设与复盘时间。一般优先调整近期一至三天；用户已经要求周计划或学期计划时按其范围完成，不重复索取同一授权。

## 写回番茄 Todo

普通任务和课表用 `tomato_create_task` / `tomato_update_task` / `tomato_move_tasks` 等单项工具；批量修改走 `tomato_export_plan` → DSH 自带 `read`/`edit` → `tomato_apply_file`，优先计划 v6 以保留历史。保持稳定 ID，不伪造学习用时，不为导入改保护规则。

正式学期、45 分钟课程、作业和测评由 `tomato_education` 写入，不塞进计划 v6。用户要求实施时在授权范围内完成写回并核对结果；仅要求建议时提供可执行方案。区分已经应用的安排、尚待核实的约束和未写回的草稿。
