# 练习：智能体编程（dsh 实操）

对应课程第 7 讲的练习，用 DeepSeek Harness（dsh）完成——你正在读这段话时就在用它。通用版练习见 `exercises.md`。

1. **实现新功能 + TDD**。在 dsh 里让智能体为你项目实现一个小功能：先让它写测试，你审核测试是否抓住了意图，再让它实现，最后让它自己跑测试进入反馈循环。观察：检查失败时它会不会自主迭代修正？对照讲义「让模型进入反馈循环时最强」的论断。
2. **修复错误（反馈循环）**。给 dsh 一条编译器/linter/类型检查器报错（如 mypy 或 ruff），让它修复并自行重跑检查验证。在 Trajectory 轨迹视图里观察「跑检查 → 看结果 → 再改」的工具调用循环——这就是讲义说的「每次工具调用/响应 = 一次推理」。
3. **代码审查**。让 dsh 审查你尚未提交的更改。先点名加载 `code-review` skill 再让它审，对比有/无该 skill 时的评审质量——体会「Skills 按需加载」对输出的影响。
4. **理解代码**。向 dsh 问一个你熟悉的代码库的问题（如「这个仓库里 X 是怎么实现的」），逐一验证它的回答是否准确——审查 AI 输出，而不是照单全收。
5. **作为 Shell 使用**。用自然语言让 dsh 完成一个 shell 任务（如「用 find 找出 30 天前修改过的文件并按大小排序」），再自己写出等价命令对比。
6. **氛围编程**。从零 vibe coding 一个小应用，不手写一行代码；完成后自己逐行审查产物，记下你发现的问题数。
7. **实习生模型与中断**。故意给一个含糊的需求，观察它走错方向时你是如何用文字反馈纠偏、或直接中断它的——对照「实习生」心智模型。
8. **确认与安全**。观察 dsh 对可能有害操作（删除文件、改系统配置）的确认提示与文件沙箱限制，对照讲义「默认对可能有害的工具调用弹确认，先读再同意」。
